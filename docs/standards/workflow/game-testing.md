# 游戏测试与场景保护

范围：Lobecorp 项目专项；来源：原工作流程对应章节；维护：2026-11-10。通用授权与执行遵守[项目入口](../../../AGENTS.md)所指共享协议，本文不产生新授权。

## 后台输入与测试边界

- 允许不同工作区并行进行非性能游戏测试（逻辑、功能、交互与视觉验证），各自使用独立游戏实例、端口、存档和证据目录；不因另一工作区存在游戏、Debug 或普通 GPU 渲染就要求等待释放。实体输入、焦点和窗口操作仍遵守本节边界，不互相抢占或操作其他实例。性能基准、GPU 写次数计量及同负载 A/B 测试仍须协调独占测量资源，避免其他游戏负载影响测量；并行功能测试结果不得作为性能证据。

2026-11-01 用户明确要求避免测试抢鼠标：本节以不抢实体鼠标、不强制前置和不恢复焦点为准，覆盖此前“保持／恢复焦点”的操作要求。焦点状态只读记录，不能因失焦自动拒绝整轮。

- 允许游戏实例内部的模拟输入、控件或GUI坐标点击、后台定向输入及结构化MCP/API。游戏内部Screen/GUI交互与系统屏幕控制按实际副作用区分，不因工具名称或“模拟／坐标点击”本身一概拒绝。
- 对已核对 PID／窗口句柄的本轮游戏，仅允许一次非激活最大化和不抢焦点的防最小化；不得调用 SetForegroundWindow、glfwFocusWindow 或循环 ShowWindow／restore 维持前台，不得移动、捕获、隐藏或居中系统实体鼠标。不能无副作用实现的能力须报告，不以抢焦点循环代替。
- 不因失焦次数、瞬时 focused 状态或曾失焦一票否决、拒绝测量或丢弃整轮。实际前后台与失焦时间线据实记录，不伪称全程聚焦；性能测量的负载、采样与证据完整性检查继续保留。
- 调用前按接口实现、文档或已有证据核对实体输入及窗口副作用；不能通过实际抢占实体鼠标来试验。本条只调整当前已授权任务的测试方法，不扩大业务、安装、重启或跨工作区写入范围，各工作同步自己的子代理和接续记录。


## 测试场景保护

- 出现新的测试需求或可能需要新场景时，新增独立场景实现、ID 和配置，保留既有场景；只有用户明确要求修改指定既有场景时，才修改其实现或语义，必要的共享注册仅作追加。

## 测试窗口原生最大化

窗口边界遵循[共享原生最大化规则](C:/Users/wang_/.agents/standards/runtime-cleanup.md#测试窗口的原生最大化)。本节只维护Lobecorp启动契约。

启动时设置`-Dlobecorp.developmentWindowTestPolicy=true -Dlobecorp.developmentWindowTestMode=native`，并在本轮独立gameDir的`config/fml.toml`预先写`earlyWindowControl=false`，保持窗口模式、不要启用全屏。这只关闭该测试目录的NeoForge早期加载窗口，不修改用户原目录或全局配置。

执行顺序：

1. 启动前准备独立目录与配置，核对目标进程归属。
2. `DevelopmentWindowMixin`在`Window.createGlfwWindow`实际调用`glfwCreateWindow`前设置`MAXIMIZED=true`、`FOCUSED=false`、`FOCUS_ON_SHOW=false`、`CENTER_CURSOR=false`；最大化发生在创建时，不是在测量中执行。
3. 仅构造阶段保留已最大化窗口，防止初始`setMode`恢复普通窗口；构造结束后从真实GLFW读尺寸/位置并同步内部缓存，安装原有防最小化消息链。
4. 首次可见显示后只读核验`IsZoomed`、`GetWindowPlacement.showCmd=3`、`GLFW_MAXIMIZED`以及前台句柄与帧缓冲；检查`event=first-visible`日志，不能仅看尺寸。没有正确创建钩子（例如复用了早期窗口）就记录未完成，不做抢焦点补救。

自动脚本和四个`Horde 开发 - 基线/A/B/C`入口按本节配置。需要复现旧批次时可显式设置`lobecorp.developmentWindowTestMode=workarea`，它只是旧铺满模式，不作为原生最大化通过。历史性能批次窗口策略保持原记录，不追认新策略。
