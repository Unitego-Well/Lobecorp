# Java 包整理审批计划

状态：2026-10-05 用户批准第二版方案 1，源码迁移完成。原清单 269 类中实际迁移 266 类；按保留强关联小组的执行边界，ConductorHud、ConductorControls、ConductorLdlibScreen 保留在 client.conductor。检查结果见系统修改记录。工具统一归根 util，世界内实体及机制归 world，下级按“作用 → 类型”分类。以下包名均省略
`org.unitego.lobecorp.` 前缀。

IDEA 当前盘点为 416 个手写 Java 文件。本方案拟移动 269 类、保留 147 类，替代第一版 121 类方案；扩大部分包含 world
归类及与“作用 → 类型”相关的客户端、注册和 Mixin 目录调整。精确清单见文末，不把计划当成已实施结构。

已通过当前项目的 MixinMCP 查询确认：原版 Entity、Brain 位于 `world.entity`、`world.entity.ai`，Item 位于 `world.item`
，MobEffect 位于 `world.effect`。这里保留 world 语义并省略无实际需要的原版层级。

## 执行边界

- 使用 IDEA 移动重构，按功能域分批更新 Java 引用；不重命名类或改变资源 ID、翻译键、数据协议。
- 移动前检查全部引用和跨包可见性。无法保持已有公开接口时保留相关小组，不为移动扩大成员可见性。
- 每批保留用户已有暂存、未暂存修改，格式化涉及类，不格式化 JSON 或生成输出。
- 本方案建议保留 `util`、`client`、`registry`、`mixin`、`config`、`event`/`events`、`network` 等统一入口根包；其下优先按作用组织，再按类型细分。示例：
  `util.photon.editor`、`client.entity.…renderer`、`mixin.photon.editor.client`、`registry.conductor.client`
  。基础入口是对通用分包规则的明确约束，不改为散落各作用域的 util/client/registry。
- `world` 收纳世界内的实体、物品、状态效果及命中框。共用实体机制归 `world.entity`，具体实体技能先进入对应实体作用域，再放入
  `skill`，不使用 `world.entity.skill.abnormalitie.…`。
- 不逐字复制原版所有目录，不机械为每个类创建子包；公共协议、跨域入口和强耦合组保留必要的共享层。
- 包迁移完成后经 IDEA 编译、Data 和诊断检查；方法拆分与提前返回单独按职责处理，保持生命周期、执行顺序和副作用。

## 批次与批准后的规范同步

1. 根 util 分类、ProviderBuilder 归位。
2. world 实体、技能、状态、属性、物品、效果和命中框；同一负责人更新共享引用。
3. 客户端、指挥家具体作用域与注册归类。
4. Photon 模块与 Mixin 路径更新。
5. 批准后同步 AGENTS.md、Java 架构说明和专项规范中的旧路径；现有规范与本方案的冲突不默认为已经批准。
6. 分批 IDEA 格式化、诊断、旧引用检查，最后按大型修改要求统一 IDEA 编译、Data 和生成资源检查。

本轮按批准方案执行上述批次。迁移、Mixin 配置及编译/Data 的实际结果统一记录在 [系统修改记录](systems/changes.md)，未完成的检查不得视为通过。

## 实际保留的关联小组

ConductorHud 调用 ConductorControls 的 protected hoveredLivingEntity，ConductorLdlibScreen 调用 ConductorHud 的 protected drawTooltip。按本计划“无法保持已有公开接口时保留相关小组”的边界，三类保留在原 client.conductor，未扩大可见性，其他指挥家客户端类按清单分类。实际计数为 266 类迁移、150 类保留，共 416 类。
