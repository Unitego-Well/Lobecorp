## 当前已确认的中转模型

- DS仅通过DSH（DeepSeek Harness）调用；不得通过Codex子代理、独立Codex DS聊天或直连模型API调用，也不得将这些入口作为DSH失败后的兜底。GPT子代理仍是GPT，不得称为DS。
- 保留用户指定的中转站 `deepseek-v4.1-flash` 与最低 `low` 偏好。每次派发前通过DSH核对实际profile、provider、模型名称和ID、支持的推理档及工具能力；只使用实际支持的参数。未知或无法核对时明示缺口，不声称已设置或可调用，不擅自换提供方、官方路由、Pro或其他型号。
- 旧Codex目录中的 `ccs-deepseek-2/deepseek-v4.1-flash` 仅是历史定位记录，不是DSH模型ID，不得直接填入DSH。DSH可执行文件、目录或模型可见不等于模型请求成功，也不证明余额、服务、工具或运行注入正常。
- DSH入口或指定路由不可用时报告具体缺失能力，由负责人在已授权范围内接手或继续独立工作；不修改模型、提供方、MCP、密钥或DSH配置来绕过限制。故障结论只对应实际profile/provider/model、路由、时间与证据。

## 何时使用DS

- 优先用于重复查找、批量比对、文档分类、链接检查、规则核对、数据整理及验收标准明确的局部任务。
- 可以承担独立模块实现、局部修复和测试编写，但必须提供足够上下文、独占文件范围、行为边界和可核实的验收标准；负责人审查真实差异后集成。
- 紧密耦合的架构决策、跨模块冲突、用户意图判断和最终验收由负责人处理；可以让DS提供证据或独立审查，不把责任转交给完成声明。
- 任务已经明确时自主在DSH内派发获准的DS任务，不为普通委派重复申请许可；可见会话、跨聊天发送消息和外部服务仍遵守当前工具所需授权。GPT子代理、Codex聊天和DSH会话是不同入口，不得混称或替代。
- 停工、迁移或审计期间只执行该阶段获准的记录和核对，不借委派恢复业务实现或游戏测试。

## DS单类任务与主线职责

- DS会话名称必须采用 `DS-工作区名称-当前任务`，工作区名称对应实际所属工作区，当前任务须具体明确。创建时显式设置名称；复用会话承接新任务时同步更新任务部分，不沿用已结束任务的名称。
- DS负责执行，主线负责方案决策、任务分配、审核和验证。一次只派一个阶段的任务：问题查询、优化研究报告、编写计划或实际编写；不将后续阶段打包为自动执行授权。
- 主线按实际影响判断复杂度。边界明确的简单任务（如配置项新增、选项或默认值调整）采用简化流程：DS提交修改计划 → 主线第一次审核 → DS实际修改并做必要验证 → 主线第二次审核实际差异与证据后收尾；不强制先独立查询与优化研究。不得仅凭“配置”等关键词把跨系统迁移判为简单任务。
- 复杂UI重设计、系统协议变化或多系统耦合任务采用完整流程：查询 → 优化研究报告 → 主线审核并选择方案 → 编写计划 → 主线审核计划 → 实施与必要验证 → 主线审核完成结果。查询收集事实、证据、差异与缺口；研究报告整理优化方向、依据、影响和风险，DS可提出候选方案，最终方案选择由主线负责。
- 两种流程的修改计划均须明确修改范围、实施步骤、行为边界与验证方式。计划审核通过后才单独派发实际编写，不将计划与实施打包为自动跨阶段授权；简化流程不取消完整上下文、独占写集、WIP保护、必要验证和主线验收责任。
- 实际编写执行审核通过的方案、计划和独占范围；每阶段均须给足上下文、需求、工具用法及验收要求。发现方案缺口或需改变方向时先回报主线，不擅自扩展。必要检查按当次任务包执行，最终审核与验证责任仍由主线承担。
- 主线派发后持续跟进至任务闭环：等待阶段结果、审查证据、纠偏并推进下一阶段，不止于派发或中途状态汇报。优先使用主动回报或工具支持的有界等待，避免高频轮询；实质需要用户决定或外部条件时明确阻塞，暂停依赖步骤并继续独立的已授权工作。停工指令始终有效。
- 新问题查询与已确认问题研究可并行，须分别派发、边界独立且写入范围不重叠；不得让同一会话并发承担冲突任务。
- 完成后主动向任务包指定的所属主聊天回报结果、证据与未完成项，主线无需持续轮询。任务包须保留直接用户授权来源、接收聊天和发送范围；工具不支持或缺少发送授权时在当前聊天报告缺口，不擅自跨聊发送。
- DS会话无异常且上下文压缩累计不超过3次（含3次）时可以保留复用，不因单批任务完成立即归档或移除。复用仍须逐次给出完整的单类任务包；需要轮换时按下文交接，不唤醒已归档会话。

## 中转调用顺序

### DSH内DS的Windows命令执行

- 派发时明确当前命令工具的 shell 和参数，不能把 PowerShell 的 `Get-Content`、`Select-Object`、`$env:` 交给 `cmd.exe /c`，也不能把 Bash 语法当作 PowerShell。先核实际 shell；支持 shell 参数时直接指定已验证的 PowerShell 可执行文件，关闭 profile，并传入真实 workdir。
- 工具仅接收命令字符串、实际由 cmd 启动时，使用已核实的 PowerShell 路径和 `-NoLogo -NoProfile -NonInteractive -Command`；含变量、嵌套引号或多行脚本时优先写任务范围内的脚本并用 `-File`，或传 UTF-16LE Base64 的 `-EncodedCommand`，不得手工叠加转义。JSON中的反斜杠只按传输层转义一次，不把序列化表示直接当作磁盘路径。
- 文本读取显式使用 UTF-8、LiteralPath 和必要行范围；需要保留原字节的校验不通过文本重编码。先检查退出码和截断，再判断执行成功；原生命令使用其真实退出码，不能以最后一条输出覆盖前面的失败。
- 首次使用某个执行入口先做一次最小只读核对：PowerShell版本、真实工作目录及目标入口的一行UTF-8读取。入口已验证且未变化时复用，不每步重测。命令解析／找不到命令与模型服务错误分开记录；同一失败命令不原样重复。
- 提交任务即表示负责人已批准该阶段，任务包中明确“本阶段已获批准，直接执行所列步骤，无须再次等待需求确认”；未批准的实施或后续阶段仍等待审核。审批拒绝、用户停工和迁移停止不能当成模型不执行；未产出时报告最后成功步骤及具体阻塞，不以继续催促代替纠正命令。

1. 核对DSH实际可执行入口及其当前帮助，通过DSH提供的只读能力核实目标profile、provider、模型ID、推理档与工具能力；命令与参数以当次帮助和实际接口为准，不读取或输出凭据，不杜撰命令。
2. 仅通过DSH派发、续接或轮换DS任务。实际命令、工作目录、会话标识及支持的最低档设置写入任务包；若不能核实指定Flash/low或必要能力，先报告缺口，不发起猜测性请求。不得把旧Codex模型ID用于DSH。
3. DSH不可用或指定路由失败时保存最后成功步骤与阻塞；负责人在已授权范围内接手或继续独立工作。禁止改用Codex DS子代理、独立Codex DS聊天或直连API兜底，不擅改DSH profile、提供方、模型或全局配置。
4. 分别记录入口发现、目录核对、请求提交、模型实际执行与产物验收。提示词落盘、会话可见、命令存在或提交成功均不能冒充模型执行、工具成功或运行注入成功；未获准的收费请求不作为探测手段。
5. 不因另一提供方的502、余额或型号错误推断指定中转不可用；故障结论限定到实际profile、provider、模型、路由和时间。保留历史和归档会话，不读取、恢复或唤醒归档聊天。

## 代理提示词与执行约束（DS和GPT共用）

**DS必须逐次显式声明**：本规则重点针对DS不能可靠遵守未在当前提示词中声明的要求。每次创建、派发、接续或更换DS上下文，都必须在该次提示词内完整写明本任务适用的读取清单、具体工具及参数、允许／禁止操作、独占范围、验证和交付条件；只给规范链接、“同上”“按之前要求”或依赖历史上下文不算满足。负责人发送前逐项检查，回收时逐项核对执行证据。GPT仍遵守相同的权限与验收边界，不因本段降低要求；此处不把两者对隐含上下文的遵守能力视为相同。

每次向DS或GPT代理创建、委派或接续任务时，负责人必须给出可直接执行的任务包，不只说“按规范处理”“使用相关工具”或“继续之前的工作”。两者采用相同的任务范围、工具权限和验收约束；本节不改变各模型已有的路由、推理档位或客户端专属规则。

接收任务的DS和GPT代理必须逐条遵守任务包：不得跳过必读资料、擅自扩大写入范围、更换受限工具、启动未授权操作、减少验收条件或将未执行事项报告为完成。遇到指令冲突、入口缺失或工具不支持时，明确回报具体缺口，继续可独立推进的已授权部分；不能靠自行解释绕过限制。负责人按任务包核对真实差异与证据，越界结果不得直接集成。

- **读取清单**：逐项列出真实绝对路径、必读章节或行范围、读取顺序与用途；明确哪些历史资料仅供参考。先核对文件存在及作用域，不把所有参考资料默认列为必读。
- **目标与边界**：写明本次要完成的结果、当前阶段（只读调查／设计／实施／验证）、真实目录与分支、独占文件、已有改动及禁止触碰项；必要上下文直接给出，不依赖DS猜测聊天cwd或历史授权。
- **工具与操作**：明确本次实际可用的工具名称、对应操作、必需参数（如projectPath、文件路径、实例／端口）及最小调用示例；说明检索、依赖源码查询、编辑、格式处理、诊断、Git和验证分别用什么。不能只写“用IDEA/MCP”，不能杜撰工具或未生效参数。
- **可用性与兜底**：分派前经DSH核实profile/provider/model、推理档、工具及目标工程；说明缺失入口或失败时的阻塞与负责人接手范围。DS调用不得离开DSH，没有授权的替代工具、安装、重启或配置修改不得自行启用。
- **执行要求**：明确做什么、不做什么，保留何种行为与数据，是否允许修改、构建、Data、测试、游戏、网络、提交或消息发送；精确区分必要验证和停工限制，不用泛化禁止条款否定已获授权的工作。
- **验收与回报**：列出可核实的完成条件、具体检查命令／运行配置、预期证据、报告绝对路径、回报对象与发送权限；分别报告已完成、失败、未执行、未验证和临时对象清理，不以完成声明代替证据。
- **自查门槛**：发送前检查“读什么、做什么、在哪里做、用什么及怎么用、能改什么、如何验收、在哪里回报”是否齐全；不适用项明确写“不适用”并简述原因，不让DS自行补全关键要求。接续任务同样重申变更后的范围、工具与剩余项。

## DS每次派发必填提示词

派发时必须显式写入默认验证边界：未另行要求时，代码完成后仅执行构建和IDEA代码检查；涉及数据生成的改动可以执行Data。不要自行运行单元/集成测试、启动应用或游戏、进行视觉验收或性能采集。构建须选择不附带测试或运行验收的任务，不能借构建隐式启动这些步骤；用户已明确要求的验证按其范围执行，未执行部分如实保留。

以下模板由主线在发送前填成真实内容，创建、复用、续接及纠偏均适用。不得保留占位符、写“同上”或只给规则链接；不适用项写明原因。只填本阶段需要的上下文，不堆入无关历史。主线先核实模型与工具，再派发；目录或工具可见不等于服务已实测。

## 委派、回报与轮换

- 任务包包含真实目录/分支、目标、必要上下文、独占文件、用户WIP、禁止事项、验收标准和报告位置。并行代理不修改同一文件。
- 检查实际文件、工具结果、报告与未验证边界；未运行验证不记成功。正文混入思考/伪工具、跑偏或完成失实时先停止实施并保存可核实交接，不反复催旧上下文继续。
- 优先复用未归档、无异常、有空闲执行范围且上下文压缩累计不超过3次的DS；超过3次时交接轮换。计数指实际上下文压缩，不是消息、续聊或任务批次数；次数无法核实时如实说明，不把未知当作0次。异常立即停止该上下文实施并交接轮换，不等次数门槛。正常待审、正在运行、等待用户选择或审批阻塞不算异常，不能靠轮换绕过审批。
