# Photon 极端场景优化计划（最坏情况）

编写时间：2026-10-25（北京时间）。范围：真实女皇激光＋光影＋多模型／多光束／多特效同时存在的最坏客户端场景。本文是**计划文档**，不代表已实现；当前已实现的只有稳定帧几何快照（`8c2fe84d`），其余阶段需逐项授权与验收。问题状态仍以 [唯一问题清单](../issues.md) 为准。

## 一、先定义“最极端”

没有场景定义就没有优化目标。本文把极端情况拆成可复现的 E0～E4，默认硬件为当前测试机（RTX 3060 Laptop、2560×1600、Sodium 0.9.2、Iris 1.11.4、Java 25），分辨率与光影固定，不用“降画质”换数字。

| 级别 | 内容 | 用途 |
|---|---|---|
| E0 | 当前真实激光：女皇三连施放，90 秒，无光影 | 生产回归基线 |
| E1 | 真实激光＋ComplementaryReimagined r5.9.3（阴影开） | 光影主战场 |
| E2 | E1＋16 动画模型＋16 静态模型＋持续粒子 | 模型实例化压力 |
| E3 | E2＋多束／多层光束叠加（至少 4 束）＋高密度粒子 | 光束与 overdraw 压力 |
| E4 | E3＋首次使用／资源重载／相机快速移动／窗口失焦恢复 | 首帧、缓存失效、稳定性压力 |

E4 是本文的“最极端”：**光影阴影、全屏后处理、多实例动画、透明光束叠加、首次编译和相机变化同时发生**。如果只在 E0 通过、E1/E2 退化，不能算优化完成。

## 二、当前证据与真实预算

| 场景 | 已知数据 | 说明 |
|---|---|---|
| E1 光影激光（对照轮） | 11033 帧，均值／P99／最长 8.158／15.519／764.657 ms；空阶段 7.521；施放窗口 8.841／8.017／7.846；GPU 均值 7.722；CPU 3.522 | 当前代码的可用对照，不是稳定 A/B |
| E0 无光影激光（历史） | 约 6.3 ms 窗口、首发约 0.6～1.0 s | 与光影轮不可直接相加 |
| BenchMod 16 静态 | 快照前 `write` 为 JFR 首位（33.3%）；快照后不再居首，`ByteBufferBuilder.reserve` 30.94% | 处理完 CPU 几何后，提交缓冲成为新热点 |
| BenchMod 16 动画 | 仍以采样／逐帧写入为主，未受益于快照 | 动画帧是下一阶段核心 |
| JFR 光影窗口 | Iris 36.8%（阴影 31.5%）为 inclusive，不等于光束独占 | 不能据此直接跳过阴影 |

**结论：极端场景的预算必须同时覆盖 CPU 提交、GPU 阴影/后处理、内存与首帧，不能只看一个均值。** 当前最缺的是 E2/E3/E4 的可重复夹具，而不是又一个微优化。

## 三、目标（建议 SLO，不是承诺）

在 E1～E3、2560×1600、光影开启、无降分辨率的前提下：

| 指标 | 目标 |
|---|---|
| 施放窗口均值 | E1 ≤ 8 ms；E2 ≤ 10 ms；E3 ≤ 12 ms |
| P99 | E1 ≤ 18 ms；E2 ≤ 22 ms；E3 ≤ 25 ms |
| 单帧最长（非首帧） | ≤ 50 ms；首帧单独统计，不混入稳定值 |
| 首发到首个可视帧 | ≤ 250 ms（预热成本单独报告） |
| 渲染线程 CPU | 稳定窗口均值 ≤ 5 ms |
| GPU（有效查询） | 稳定窗口均值 ≤ 10 ms，P99 ≤ 16 ms |
| 内存 | 每个效果实例的常驻几何／快照有上限；极端 64 实例不触发持续 GC |
| 视觉 | 与基线截图／逐顶点对照无可见差异；透明排序、遮挡、光照保持一致 |

E4 只要求“不崩、不泄漏、不无限长帧”，首帧与重载成本单独列表，不能拿 E4 的异常帧证明稳定收益。

## 四、优化路线（按依赖顺序）

### P0：固定测量条件与极端夹具

- 固定窗口/刷新率、相机、粒子 seed、光影包、渲染距离；记录 framebuffer 与 display refresh，避免再次出现同机 1.6 ms 与 6.2 ms 两种地板。
- 在现有 QueenBeamPerformanceTrial 之外增加 **E2/E3 合成夹具**（16/64 动画模型、4 束叠加），复用 PhotonModelOutput，不复制一套渲染器。
- 每次 A/B 只改一个变量；同时采 JFR（CPU／分配）、GPU 查询、draw call、buffer 扩容、首帧阶段。没有 E2/E3 数据前，不进入 P1 以上的“收益承诺”。

### P1：动画模型的持久网格＋实例提交（核心）

目标：动画帧也停止逐帧 CPU 顶点展开。

1. **持久基网格**：按部件／材质组把顶点、索引、UV、法线、切线上传一次；基网格不随帧变化。
2. **每部件实例 TRS**：把模型动画拆成部件 `iPos/iScale/iRot`，每帧只填实例缓冲；原生 `MODEL/MODEL_TANGENT` 顶点阶段完成变换。
3. **顶点级形变才用 VAT**：骨骼／morph 导致的顶点变化，按“顶点×帧”烘焙 VAT；否则不引入 VAT 的内存成本。
4. **材质组**：每个（部件，材质）组合一份 BaseMesh；材质仍走现有 `PhotonModelMaterials`，不改变着色。
5. **回退**：实例化不满足等价性（透明排序、法线、部件覆盖）时，逐组回退 CPU 快照／原写入；**特性开关默认关闭，A/B 通过再开**。

这一步的验收不是“看起来差不多”，而是逐顶点属性对照＋截图＋透明交叠测试＋E1/E2 的 CPU/GPU 数据。

### P2：光束专用路径

- 先评估原生 `BeamEmitter` 的 GPU 实例化光束（每实例 start/end/width/color/UV）；若外观不满足，保留模型光束，但用 P1 的实例化网格。
- 多束叠加（E3）优先合并为“同材质实例批次”，减少 draw call 与状态切换；不同材质不强行合并。
- 不把“阴影跳过”当光束优化；当前实验已证明模型阴影跳过与 drain 跳过都无收益，见 [性能审查复测节](photon-performance-audit.md)。

### P3：提交缓冲与内存（新的第一热点）

`ByteBufferBuilder.reserve` 已在 16 静态中占 30.94%：

- 复用 Photon 的 `PhotonBufferCache`／`MappableRingBuffer` 容量，避免每帧按峰值重新扩容；
- 对固定拓扑预计算顶点数，预分配足够的 staging；
- 快照／实例缓冲设上限，极端 64 实例时按内容预算降级到原路径，而不是无限增长；
- 记录 buffer 扩容次数与字节，而不是只看分配总量。

### P4：阴影与 Iris 分层（必须先测再动）

- 用 `IrisCompat.isShadowPass()` 做**分层统计**：Photon 是否在阴影 pass 提交、提交了哪些对象、GPU 阴影耗时占多少。
- 只有证明“某类对象在阴影 pass 无贡献且占显著成本”时，才允许按对象类型关闭；不做全局 shadow skip。现有 E1 实测：模型阴影跳过 8.528 ms、drain 跳过 8.866 ms，均差于基线 8.158 ms，已回退。
- KilaGraph 的 ENTITY 路由（UV1 等）只在 A/B 证明不退化后考虑，不把它当作默认修复。

### P5：参数、命名动画与首帧

- 参数／命名动画按内容版本预编译执行计划，避免每帧 Map、List、字符串查找；复用已有 `PhotonNamedMixer` 生命周期，不共享可写实例。
- 首帧把基网格、VAT、材质管线、纹理准备移到 SETTLE 前；预热成本单独报告，不能把成本静默转给进世界或技能前摇。
- 极端 E4 的重载／取消要做资源释放账本，防止“优化后泄漏”。

### P6：极端预算与降级（质量优先）

- 实例上限、快照上限、VAT 预算、远距离 culling、低优先级效果合并——全部是**可配置预算**，不是默认降画质。
- E3/E4 达到预算上限时，优先减少不可见/屏幕外实例，不降低屏幕内分辨率或阴影质量。
- 所有降级必须有可见指标与用户可感知说明，不允许静默。

## 五、Mixin 目标（只列目标，不在本文实现）

| 编号 | 目标 | 目的 | 前置条件／风险 |
|---|---|---|---|
| M1 | `PhotonModelOutput#bakeBatches`（本项目） | 稳定帧快照已落地；后续在此接入实例化分支 | 等价性与回退 |
| M2 | `Emitter#bakeInstancedGroup` 桥 | 传入自定义 BaseMesh／实例填充／组材质 | 原生私有编排随 Photon 升级漂移 |
| M3 | `PhotonWorldRenderState` / `InstancedJob` | 构造自定义实例 Job，减少复制编排 | 记录/布局/排序必须逐项对照 |
| M4 | `PhotonPipelines` 的 instanced 格式／管线 | 添加所需属性或自定义 shader | 与 Iris、shaderpack、KilaGraph 兼容 |
| M5 | 阴影 pass 分层（`IrisCompat.isShadowPass`） | 仅对象级门控，非全局 skip | 当前 A/B 为阴性，先测量再启用 |
| M6 | 管线／纹理预热 | 降低首发编译 | 预热成本必须单独报告 |
| M7 | 参数／命名计划（本项目类优先） | 去掉每帧 Map／List | 语义、随机源、生命周期 |
| M8 | VAT／GPU 蒙皮 | 顶点级形变 | 内存、精度、Iris 兼容；VAT 不足才考虑 |
| M9 | 提交缓冲池 | 解决 `ByteBufferBuilder.reserve` | 不得跨帧持有可变数据 |

**不做**：全局跳过阴影、全局缓存可变 DrawJob、用共享可写副本替代 deepCopy、默认降分辨率／LOD、把未验证的 GPU 化写成收益。

## 六、实施顺序与门槛

| 阶段 | 内容 | 通过条件 |
|---|---|---|
| G0 | E2/E3 夹具、固定刷新率与相机、draw/buffer/首帧计数 | 可重复测到当前瓶颈，数据可归因 |
| G1 | P3 提交缓冲复用（低风险先做） | 16 静态 `ByteBufferBuilder.reserve` 明显下降，视觉一致 |
| G2 | P1 单部件动画实例化 spike | 逐顶点对照、透明交叠、截图通过；CPU 降、GPU 不退化 |
| G3 | P1 多部件／多材质／回退 | E1/E2 窗口均值与 P99 达标；失败自动回退 |
| G4 | P2 多光束／合并批次 | E3 draw call 与 CPU 下降，透明排序正确 |
| G5 | P4 阴影/Iris 分层（仅证据支持时） | A/B 有收益且视觉一致，否则不合并 |
| G6 | P5 预热／参数计划 | 首帧下降且没有转移为进世界卡顿 |
| G7 | E4 重载／取消／失焦恢复 | 无泄漏、无累积长帧、资源回落 |

每一步都必须有：基线、单一变量、同条件复测、原始帧/JFR/截图、语义回归、回退方式。**没有 G1 的缓冲数据，不开始 G2 的实例化；没有 G2 的等价性，不扩大实例规模。**

## 七、极端场景验收矩阵

| 场景 | 必测 | 通过标准 |
|---|---|---|
| E0 无光影激光 | 3 次施放、P99、首帧 | 不退化；CPU/GPU 可解释 |
| E1 光影激光 | 同上＋阴影/后处理 | 窗口 ≤8 ms 量级；P99 ≤18；首发 ≤250 ms（预热另计） |
| E2 32 模型＋激光 | 实例化开/关 A/B | CPU 下降、GPU 不退化、透明排序正确 |
| E3 4 束＋64 模型 | draw call、overdraw、GPU | 不出现 >50 ms 稳定窗口长帧；无排序错误 |
| E4 首帧/重载/相机/失焦 | 资源账本、缓存失效 | 无泄漏、无累积尖峰；首帧成本单独报告 |

视觉验收：基线／候选同机位截图、逐顶点属性对照、透明交叠与遮挡用例、Iris 开关两态；不以“截图能看”代替像素级对照。

## 八、风险与回退

- **实例化等价性风险**：透明排序、法线、部件覆盖、UV、光照可能变化；每阶段保留 CPU 快照／原写入开关，失败即回退。
- **Photon 升级风险**：Mixin 目标与私有编排随版本变化；记录 Photon 版本与目标签名，升级后重新验证。
- **Iris/shaderpack 风险**：ENTITY 路由、Missing program、阴影分层都可能影响视觉；仅按 A/B 结果启用。
- **内存风险**：VAT／实例／快照都有预算上限；极端规模优先 culling 与预算，不静默降画质。
- **测量风险**：显示刷新率、spark 后台采样、首次编译会污染数据；每轮记录实际刷新率、工具状态、首帧阶段。

## 九、未决问题

- E2/E3 夹具尚未实现；没有真实 64 实例数据前，P1 的收益只是架构推断。
- 动画模型的部件矩阵能否完整表达现有着色／覆盖语义，需要 spike 验证。
- 原生光束（BeamEmitter）与现有模型外观的差距未知，可能只能用于核心层。
- `ByteBufferBuilder.reserve` 的扩容能否通过预分配稳定消除，需要 G1 数据。
- 阴影 pass 中 Photon 对象的实际占比仍需对象级统计；当前全局 skip 已证伪。
- VAT 内存与 Iris 兼容性、GPU 蒙皮必要性，都要在 E2 后再决定。
