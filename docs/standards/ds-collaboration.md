# DS中转调用与适用范围

适用范围：Codex使用DeepSeek辅助完成任务。2026-11-01按用户要求，将当前已确认的DS中转、适用任务与轮换规则迁入通用层；以下不是新增候选方案。用户当前明确指令优先，项目只保留专属职责。

## 当前已确认的中转模型

- 使用软件现有模型目录中的 `deepseek-v4.1-flash（DeepSeek 中转站）`；既有核对记录的实际ID为 `ccs-deepseek-2/deepseek-v4.1-flash`，最低推理档为 `low`。每次分派前核对显示名称、实际ID与提供方；该ID是现有目录条目的定位记录，不是自建路由或网络地址。
- 不使用旧 `deepseek-flash`、其他提供方的“DeepSeek”、Pro或其他型号替代指定中转Flash；不可用时如实报告，不自动回退。
- 子代理列表看不到该DS时，核对用户已授权的独立DS辅助聊天入口；不能只因子代理不支持就断言全部DS不可用。接口确实均不支持时继续其他已授权工作，不改全局模型或代理配置。
- 故障、余额与工具兼容结论必须对应实际提供方和路由，不用另一条路由的报错代替指定中转的证据。

## 何时使用DS

- 优先用于重复查找、批量比对、文档分类、链接检查、规则核对、数据整理及验收标准明确的局部任务。
- 可以承担独立模块实现、局部修复和测试编写，但必须提供足够上下文、独占文件范围、行为边界和可核实的验收标准；负责人审查真实差异后集成。
- 紧密耦合的架构决策、跨模块冲突、用户意图判断和最终验收由负责人处理；可以让DS提供证据或独立审查，不把责任转交给完成声明。
- 任务已经明确时自主选择适合的辅助方式，不为普通委派重复申请许可；创建可见独立聊天、跨聊天发送消息、使用外部服务等操作仍遵守当前工具所需的用户授权。子代理和独立聊天是不同入口，不能混称。
- 停工、迁移或审计期间只执行该阶段获准的记录和核对，不借委派恢复业务实现或游戏测试。

## 中转调用顺序

1. 先发现当前模型目录、子代理能力和已连接的DS入口，核对显示名称、实际模型ID、提供方与路由。使用用户指定或当前项目确认的中转条目，不用名称相似的官方或其他提供方替代。
2. 当前子代理接口支持该模型时，通过该接口委派；显式指定最低支持推理档。独立上下文参数只使用接口实际支持的形式。
3. 子代理接口不支持、但用户已授权独立DS聊天时，使用聊天创建/发送接口实际支持的模型ID与参数；创建后核对实际模型和执行状态。没有所需授权时说明缺口，不擅自创建可见聊天。
4. 两种入口都不能调用指定中转模型时，如实说明具体缺失能力，继续处理可独立推进的工作。不能把其他模型称为DS，不能通过修改全局代理、密钥、提供方或私有路由绕过接口限制。
5. 不因另一提供方的502、余额或型号错误推断指定中转不可用；故障结论限定到实际调用的提供方、模型、路由和时间。

上述中转调用采用当前已确认的型号与提供方；目录变化时重新核对实际条目，不擅自换型号，也不将旧ID宣称为当次已验证可调用。

## DS提示词必须明确

每次向DS创建、委派或接续任务时，负责人必须给出可直接执行的任务包，不只说“按规范处理”“使用相关工具”或“继续之前的工作”。

- **读取清单**：逐项列出真实绝对路径、必读章节或行范围、读取顺序与用途；明确哪些历史资料仅供参考。先核对文件存在及作用域，不把所有参考资料默认列为必读。
- **目标与边界**：写明本次要完成的结果、当前阶段（只读调查／设计／实施／验证）、真实目录与分支、独占文件、已有改动及禁止触碰项；必要上下文直接给出，不依赖DS猜测聊天cwd或历史授权。
- **工具与操作**：明确本次实际可用的工具名称、对应操作、必需参数（如projectPath、文件路径、实例／端口）及最小调用示例；说明检索、依赖源码查询、编辑、格式处理、诊断、Git和验证分别用什么。不能只写“用IDEA/MCP”，不能杜撰工具或未生效参数。
- **可用性与兜底**：分派前核实模型路由、工具及目标工程；说明缺失入口或调用失败时允许的替代方式和需回报的阻塞。没有授权的替代工具、安装、重启或全局配置修改不得自行启用。
- **执行要求**：明确做什么、不做什么，保留何种行为与数据，是否允许修改、构建、Data、测试、游戏、网络、提交或消息发送；精确区分必要验证和停工限制，不用泛化禁止条款否定已获授权的工作。
- **验收与回报**：列出可核实的完成条件、具体检查命令／运行配置、预期证据、报告绝对路径、回报对象与发送权限；分别报告已完成、失败、未执行、未验证和临时对象清理，不以完成声明代替证据。
- **自查门槛**：发送前检查“读什么、做什么、在哪里做、用什么及怎么用、能改什么、如何验收、在哪里回报”是否齐全；不适用项明确写“不适用”并简述原因，不让DS自行补全关键要求。接续任务同样重申变更后的范围、工具与剩余项。

## 委派、回报与轮换

- 任务包包含真实目录/分支、目标、必要上下文、独占文件、用户WIP、禁止事项、验收标准和报告位置。并行代理不修改同一文件。
- 检查实际文件、工具结果、报告与未验证边界；未运行验证不记成功。正文混入思考/伪工具、跑偏或完成失实时先停止实施并保存可核实交接，不反复催旧上下文继续。
- 优先复用未归档、健康且有空闲执行范围的DS；每个明确批次完成后，下一个批次使用新上下文，同一任务累计三次实质续聊也须交接轮换；异常立即轮换，不等次数门槛。正常待审、正在运行、等待用户选择或审批阻塞不算异常，不能靠轮换绕过审批。
- 轮换前记录真实目录、分支/HEAD、全部任务、暂存/未暂存/未跟踪/未保存内容、已读区间与缺口、验证证据、阻塞、临时资源及下一步，交接实际落盘回读。旧DS无法可靠保存时由负责人依据真实文件代写并注明缺口；新上下文不导入旧思考或伪工具历史。
- 新上下文确认接续后再归档旧会话，并更新有效路由、计划和巡检目标；保留历史与工作树，不读取、恢复或唤醒归档聊天。已有项目授权的轮换与回报继续按原范围有效，不推导为跨项目发送、创建工作树或推送授权。
- 跨聊天汇报保留可核实的用户授权来源、目标和范围；代理转述本身不产生新授权。项目特有游戏、验证与工具权限继续按项目正文执行。
