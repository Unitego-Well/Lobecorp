# 世界特效性能前后对比（2026-10-18）

本轮主要改正常世界中的运行时复制、动画混合分配和顶点缓冲复用，未减少粒子数量、模型层数或修改着色器。单实例最低一秒帧率
86→108，四实例 31→54；四实例 P99 56.950→32.824 ms。 **仍未达到稳定 100 FPS**：单实例 1% low 52.32 FPS，四实例平均 81.67
FPS，不能以单实例平均 139.75 FPS 代替稳定性验收。

## 实现与边界

| 改动           | 原行为                                                             | 当前行为与约束                                                                                                                                              |
|----------------|--------------------------------------------------------------------|-------------------------------------------------------------------------------------------------------------------------------------------------------------|
| 模型运行复制   | 出生时规范模型 JSON 反复 UTF-8 编码、NBT 字节复制，并导出派生依赖  | PhotonRuntimeCopyUtil 的线程作用域仅在运行复制期间改用 StringTag，复用不可变 JSON；可变材质、参数和对象仍独立，正常保存／导出继续原 ByteArrayTag 和完整依赖 |
| 模板动画控制器 | 完整复制定义后又安装筛选过的动画库                                 | 精确控制器类型直接建立独立副本，保留 ID、名字与局部变换，再安装筛选库；子类继续原复制路径                                                                   |
| 父节点归属     | 第一版快路径误用 copyTransformFrom，连接源运行树的实际父节点       | 当前仅复制局部变换和内部 ID，由新 FXRuntime 按内部父 ID 建立自己的树；12 项加载回归检查独立父节点、局部旋转／缩放、源树不变                                 |
| 动画混合       | 每次属性采样创建流、绑定列表、贡献映射与列表，重复克隆私有结果数组 | 每层复用绑定工作区，合成工作区按调用独占；递归时另借，finally 清空，最多保留一个备用区；安装后的数值函数仍持有独立贡献快照，保持叠加顺序与重入语义          |
| 原生顶点缓冲   | 空闲最多64项／8MiB，找不到足够大的项时会丢掉遇到的小项             | 最多128项／16MiB，保留小项供其他请求，单项上限仍1MiB；所有权与帧末／退出／重载释放规则不变                                                                  |

## 条件与统计定义

锁定 Minecraft26.1.2、NeoForge26.1.2.100、Photon26.1.2.3、LDLib2 26.1.2.42、Java25。GPU 为 NVIDIA GeForce RTX3060
Laptop，OpenGL；分辨率2560×1494，游戏主窗口最大化，VSync关闭，持续期实际 NONE／260，Bloom与现有材质配置保持。正常世界，无编辑器画面；特效资源
lobecorp:the_queen_of_hatred/laser_spell。

固定独立 RemotePlayer 相机坐标 (-0.5,56,-2.5)、yaw/pitch=0/0；不让玩家移动改变采样视角。特效根位置 (2.5,57.62,7.5)
，四实例各自Y递增0.1，朝向Y=-π/4。每实例使用独立固定种子0～实例数-1。三个40秒周期：0秒charge_start，10秒charge_end+laser_start，35秒laser_end，38秒检查余量。120秒完整记录，不在正式采样期间编译、编辑或展开JFR调用栈。

前后都暂将 inactivityFpsLimit 设为 MINIMIZED、pauseOnLostFocus=false，结束恢复 AFK／false；未保存 options。
**单实例前稳态全部未获得焦点，单实例后全部获得焦点**；两者都未缩小、未最小化且
NONE／260。四实例前后均全部获得焦点。操作系统后台调度仍可能不同，因此单实例不是严格前台A/B。运行顺序、JIT／堆状态、世界与其他进程负载并非完全隔离；每配置只有一份120秒记录，收益是本机观察值，不提供总体置信区间。

- 主比较取预热稳态55～74、95～114秒，两个端点都在同一个窗口的完整帧间隔；合计约38秒。
- 平均FPS=完整区间帧数／区间间隔总时长。
- 1% low=1000／最慢ceil (N×1%)帧间隔的均值；0.1%同理，不使用瞬时FPS排序均值。
- 最低一秒FPS=窗口内每100ms滑动一次，统计 (start,start+1]的render入口数；不等于最慢单帧倒数。
- P50／P95／P99／P99.9采用排序后线性插值；抖动用帧间隔总体标准差。
-
CPU为上一Minecraft帧或当前GameRenderer.render，范围与表头一致；GPU仅GameRenderer.render，异步查询，排除tick、extract、present、swap和limiter。不是系统占用率，也不能把CPU和GPU相加。
- Java堆分配是渲染线程相邻render入口的分配差值，不含其他线程、原生堆和显存。
- JFR均使用profile配置；GC为稳态窗口裁剪后的GCPhasePause。执行与native采样频率不同，不混算CPU占比。GC与长帧只说明时间重叠，不证明整个长帧由GC造成。
- 首次释放窗口10～11.9秒与首周期截图成本分开说明；前客户端此前已经运行，后客户端重启， **不作为等价冷启动对照**
  。截图只在首周期，主稳态比较没有截图动作。

## 尚未完成与后续策略

-
稳定100FPS仍未达成，尤其四实例。采样仍指向模型sampleRenderMesh位置／法线数组、partVertices向量与每顶点writeMesh／normalize；需要独占姿态工作区和刚性模型GPU变换，先确定geometry、collector、上传及帧末释放的所有权，再实现，不能直接池化被下游持有的数组。
- 动画参数按UUID.toString与stream逐次查找、以及Layer绑定列表增容仍有成本；下一轮可用不改变公开可变参数列表语义的当次查找／快照和合适容量，防止缓存旧参数、名称、mute或排序。
- 本轮没有实现GPU实例化、通用OIT、事件时间轴索引或裁剪未知着色器Alpha。ShaderGraph仍走原流程，不把不支持的材质猜作可安全预写。
- 渲染层次、视深排序和不透明遮挡的统一入口与默认模式，是用户随后提出的独立变更；当前尚待确认合并为一个模式还是保留独立控件，
  **本表不宣称该变更已经实现或纳入采样**。既有工程显式设置未改。
