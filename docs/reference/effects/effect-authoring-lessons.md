# 特效制作经验与维护规范

整理日期：2026-10-15。来源为本对话已完成的制作过程和 Lobecorp 当前文档；这是经验提炼，没有重新观看视频、运行性能测试或进行外观验收。

## 从错误表现反推制作问题

| 观察 | 提炼出的做法 |
|---|---|
| 看错视频，播放器自动进入下一条 | 记录视频标识、标题与时长，采样后暂停，避免只凭浏览器当前画面继续制作 |
| 最终画面像，教程分解步骤却缺失 | 建立完整步骤覆盖表；阶段帧只检查节奏，不能替代构成检查 |
| 蓄力像“出现／缩放”，没有汇聚动作 | 给独立载体设计空间运动、旋转和出生／消失过程，不能只让整体淡入或缩小 |
| 持续粒子一阵一阵出现 | 对照原生默认发射器，检查累计速率、取整、预热、队列与上限；用相邻 tick 新增粒子身份验证 |
| 几何缩放系数一致，画面仍然扁 | 先看原始网格各轴尺寸，再看参考尺寸、父级和动画，不能只比较关键帧系数 |
| 冲击波移动或围绕中心伸长 | 固定根端，沿轴向伸长；径向收细独立控制，侵蚀阶段按需求停止收缩 |
| 球壳接缝和条带纹理怪异 | 检查面角 UV、接缝、流向和纹理密度；球面效果可按三维方向采样，不能一律套用平面 UV |
| 光效很白，层次却不正确 | 先确认无 Bloom 的轮廓、遮罩、色层与侵蚀，再调整亮度和后期 |
| 调了参数但看起来没生效 | 区分配置基础值与运行时覆盖值，使用实际命名动画实例验证 |
| CPU／GPU 都高 | 先区分模拟、提取、绘制和 GPU 指标，再定位分配、重复采样、面数、透明叠绘和着色器成本 |
| 保存、退出后用户失去焦点 | 通知不应抢焦点；只清理本轮控制状态和断点，交还操作时检查实际输入状态 |
| 文件移走后材质丢失 | 迁移依赖闭包及模型字节数组中的 JSON 引用，检查包内完整 ID 与资源根，不只做文件移动 |

## 可复用的工序

先匹配比例、方向、观察镜头和整体节奏；再做运动与生灭，然后细化材质、火花、环境与后期。使用同一参考的阶段帧对照，记清视频讲解时间、效果时间和工具时间单位。

先复用当前引擎原生能力与 API；只有确认能力缺口才补通用接口。批量编辑在边界读取状态，失败时重新定位，不能靠反复改一个参数猜结果。大模型、SNBT、图片 base64 和长日志只保留任务需要的摘要。

对象池只池化明确不会逃逸、可可靠归还的临时工作区；缓存定义与可变播放实例分开，容量及失效条件必须明确。降面时保留轮廓、接缝 UV、硬边、Morph 下标和法线，不把面数下降直接称为 GPU 利用率下降。

## 当前 Lobecorp 案例与证据边界

当前工程见[女皇星束资产](../../systems/effects/queen-star-beam.md)：`src/main/resources/assets/lobecorp/fx/the_queen_of_hatred/queen_star_beam.fxproj`；运行 ID 为 `lobecorp:the_queen_of_hatred/queen_star_beam`，命名动画为 `queen_star_beam`。保留 31 对象、17 图及 200 tick 时序。案例使用 length／width／intensity／enabled；这些名称和数值不是所有引擎的固定规范。

目录迁移时，开发环境直读源码 assets／fxpacks，发行加载保留资源管理器流程，本机布局仍在 run。144 文件备份核对、原生包 18 文件且 warnings=[]、31 对象及 17 图读取成功已有记录；完整发行 JAR 和迁移后的视觉复验未执行，最近项目路径最后同步受 Debug 会话断开阻断。

模型协议把 asset／assetJson 保存在 UTF-8 字节数组中；只扫描 NBT 字符串会遗漏引用。原生 GUI 与 MCP 包导出的默认命名不同，重新导出必须显式保留完整嵌套 ID。旧 refined／V3 路径仅作为历史证据。

具体入口及限制以[女皇星束](../../systems/effects/queen-star-beam.md)、[开发资源](../../systems/core/resources-datagen.md)为准；实现与采样证据见[模型运行缓存](../../systems/photon/photon-model-effects.md#运行缓存与采样开销2026-10-15)、[性能历史记录](../../records/photon/photon-effect-authoring-history.md#v3-性能优化2026-10-15)和[修改记录](../../records/changes.md)。网易附加包复用制作方法，具体模型格式、材质、时间单位和 SDK 能力按网易项目核对，不移植 Photon 的协议或 Java 实现。

## 维护与交付

当前用法、可复用方法、引擎限制、案例参数和历史证据分别维护。默认入口只负责路由，不复制完整 API、故障日志或案例全参数；未涉及的专项资料不预加载。

交付可编辑工程、运行定义和依赖；按实际完成情况记录变量、时间单位、输出路径、备份、未解决问题和验收范围。清理只覆盖明确归属且获授权的资源，不能删除用户文件。
