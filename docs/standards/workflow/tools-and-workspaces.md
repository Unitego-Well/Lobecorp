# 项目工具与工作区边界

范围：Lobecorp 项目专项；来源：原工作流程对应章节；维护：2026-11-10。通用授权与执行遵守[项目入口](../../../AGENTS.md)所指共享协议，本文不产生新授权。

## 工具、编辑与并行

- 优先使用已有 Skill、MCP、IDE、工具和 API。
- 所有工作区开发与验收统一使用 spark、BenchMod、mc mcp、idea mcp、debug，按[项目工具链](../../tooling/README.md#项目工具链)承担各自环节，不得用其他方式替代对应环节；本要求不统一各工作区端口或环境配置。
- 操作必须显式指定所属工作区真实目录，不根据聊天显示的 cwd 推断归属，不跨工作区写入。项目与公共规范同步必须通过 Git 已提交内容进行三方合并，不用文件复制或整文件覆盖代替；逐段审查冲突并保留分支补充；原始 dev 维护公共地基与协调入口，不代替分支负责人验收。
- 协作仅使用未归档且未被[对话路由](../../tooling/workspaces/workspace-layout.md#对话路由)排除的 AI 聊天。保留的旧对话只完成已授权收尾，不派发之后的新任务；轮换后按新ID检索、跟踪和调度，不以标题重新选回旧对话。不检索、恢复或唤醒已归档聊天。
- 工作区统一位于原始仓库 `.workspace/lobecorp_<content>`，由 Git worktree 管理并由原始仓库忽略；现有聊天完成后再为后续任务开新聊天，旧路径兼容链接不得提前移除。详见[工作区目录](../../tooling/workspaces/workspace-layout.md)。
- Minecraft MCP 只消费外部仓库构建并提交到 `lib` 的 JAR 和桥接制品；不恢复 `modules/minecraft-mcp` 或源码子项目。升级和隔离见[制品规范](../../tooling/minecraft-mcp/minecraft-mcp-artifacts.md)。
- 默认使用不抢占实体鼠标或用户实际输入、不干扰当前编辑状态的 MCP/API；被测游戏窗口的一次非激活展开与只读焦点记录按下方测试边界执行。需要并行开发时，优先使用独立工作树、项目目录或 IDE 实例隔离；不得并行修改同一物理文件。后台模拟与GUI测试按[后台输入与测试边界](game-testing.md#后台输入与测试边界)执行。
- 游戏输入、最大化、焦点与实体鼠标边界只维护在[后台输入与测试边界](game-testing.md#后台输入与测试边界)。每轮测试必须截图归档并给出可查看路径；焦点时间线、失败轮及其他证据由所属工作的 BenchMod 与问题清单记录。性能测试中 Spark 从进入测试持续到结束，停止后等待上传链接或输出落盘再关闭客户端；Sodium 保持加载。
- Git 操作优先使用原生 Git，指定真实工作区并后台执行；存在未保存 Document 时先核对。确需 IDE 专属状态时使用已加载扩展，不自动重启 IDEA。
- 常规 Client 启动不得自动放大窗口或限制最小化。以下窗口测试策略仅由显式 `lobecorp.developmentWindowTestPolicy=true` 开启，Gradle 的 bench 运行入口显式设定该属性；普通 Client 不设定。测试客户端启动后仅对同一实际游戏窗口执行一次非激活最大化；不得在每个场景或每 tick 重复最大化、还原、前置或聚焦。防最小化和后台运行处理必须避免抢焦点、捕获或居中实体鼠标。Photon 等编辑器仍嵌入游戏窗口，按游戏主窗口核对状态。
- 连贯且步骤固定的操作合并为一次 MCP/API 调用或批处理，只在开始、结束及有分支或失败时读取必要状态，避免逐步重复查询。进入新测试世界优先复用开发环境的 Create Test World 快速入口；已在所需世界时直接继续，不重复进入。
- 普通文件读写、文本修改、替换、补丁与查找使用 CLI，不依赖 IDEA 控制台；符号语义、引用与调用关系、类或变量等语义重命名、其他重构、未保存 Document、编辑器诊断与调试使用 IDEA MCP，遵循共享协议与智能路由。
- IDE/MCP 不支持的二进制资源清理，在核对真实工作区、精确路径、有效备份及引用后，可直接使用 CLI 执行，无需逐次确认；保留其他 WIP，不使用通配符扩大删除范围。本条不授权其他破坏操作。
- IDEA/MCP 不可用时，普通文本操作仍可通过 CLI 完成；需要 IDE 语义或未保存 Document 能力的操作须报告具体缺口，不用文本替换冒充等价能力，不擅自安装、重启或改配置。
- 每次修改前后按操作核对文件信息：普通文本使用 CLI 与 Git；涉及符号、引用、未保存 Document 或诊断时使用 IDEA/MCP。磁盘修改前须确认没有未保存版本，存在时通过 IDE 合并，保留原编码、换行及已有修改。
- 大型修改前后检查文件内容、错误、警告、语法、引用和 Git 状态；只改数值等极小修改时，只检查相关部分。
- 允许并行处理不同文件，但必须明确文件归属，禁止并行修改同一个文件。
- 保留未修改区域的原文件排版及用户已有暂存、未暂存、未跟踪和编辑器未保存内容；目标文件已有用户修改时，先通过 IDEA/Git 对比，再在同一文件中最小范围合并，不擅自覆盖、重置、暂存、提交或删除。
- 代码格式属于编辑规则，新增代码文件与本次修改行的格式调整已包含在本次编辑范围内，不另行询问格式化授权。完成代码修改后，按语言及项目格式使用适用的
  CLI 格式工具；需要 IDEA 格式能力时使用 IDEA。新增代码文件可格式化全文件，已有文件仅格式化修改行或明确涉及的类，优先使用行范围，不触及未修改区域。只有用户明确授权的整个项目整理任务才允许按包或项目范围格式化。
- 格式化默认关闭额外的导入优化和成员重排；需要这些操作时，只处理本次明确授权的范围。
- 格式化前确认文件类别与来源。用户提供的 JSON 等资源文件、数据生成输出、第三方文件和二进制资源不纳入自动格式化；需要修改资源内容时保持其原始排版，除非用户明确要求格式化该文件。
- 只修改当前任务明确涉及的内容，不进行无关重构、清理、重命名、格式化或修复。
