# Lobecorp 工作流程与收尾规则

本文件从项目根 AGENTS.md 按职责拆出，与根文件具有相同约束效力；仅在文件修改、工具操作、接口复用或收尾涉及对应规则时读取适用章节。用户当前明确指令仍优先。拆分不改变原规则，不授权顺带修改或主动运行。

## 开始任务前

- 处理开发任务前，先读取相关 Skill、项目规范和专项规范，并制定简要计划；只读适用章节，不默认加载全部参考、修改历史或案例。
- 优先通过 IDEA/MCP 做只读检索来确认术语、类型、引用和现有实现；仍无法确定时再向用户提问。
- 只有缺失信息会实质改变需求、范围或关键选择，且无法从上下文核实时，才及时提问；常规可逆选择自主处理。已有明确授权不重复询问，未确认的实质需求不得猜测。
- 每次只问一个问题；提问使用“选项 + 推荐意见”的形式，并把推荐选项放在第一项。用户选择后，明确记录选择结果。
- 澄清与选择问题提问优先使用当前软件提供且可用的提问 API；没有可用的提问 API 时，直接在对话中提问。一次仍只询问一个实质问题；等待当前问题回答后再问下一个，用户尚未回答时，不视为已选择或确认。
- 涉及向后兼容、旧格式读取、迁移或兼容分支时，默认先询问用户是否需要兼容，不自行保留或新增兼容逻辑；用户已明确选择时按该选择执行，不重复询问。本次模型特效文件采用 `.mfxproj`、`.mfx`、`.mfxpack`，不兼容此前模型工程与定义格式。
- 游戏资源的目录名与文件名只能使用英文，扩展名及格式要求保留；用户提供中文名称时，先确认英文形态，再创建或重命名。此规则为项目通用规范，适用于所有工作区；不据此批量重命名无关存量资源。开发代码文件名及特效内部标识符仍遵循各自规范。资源命名与定义调用见[资源规范](../systems/resources-datagen.md#文件命名与运行定义)。

## 系统文档与修改记录

- 各功能与系统维护对应文档，统一入口为 `docs/systems/README.md`。
- 每次修改前，先查看系统索引和相关文档，确认是否已有功能、接口和规则；文档仅作为索引与参考，可能不完整或过时，必须再通过 IDEA 核对当前源码、依赖、类型和引用。文档未记载不代表功能不存在。
- 修改完成后同步相关系统文档；新增、删除、重命名和包迁移时同步索引、入口和链接。记录职责、公开接口、生命周期、配置、资源、协议、依赖以及已知限制的实际变化。
- 每次修改后在 `docs/systems/changes.md` 记录日期、范围、关键文件、实际检查结果与备份；明确区分已实现、计划、历史证据、未验证及受阻内容。读取时仅查相关日期或系统，不默认通读历史。
- 解决或修正问题后，在对应系统文档记录问题现象、已确认的根因、修复方式和防止再次踩坑的维护要点；修改前检查这些记录，避免重复引入已解决的问题。推测与未验证结果必须明确标注，不能当作已确认根因。
- 文档补充不构成额外代码修改授权；生成输出保持只读，不在其中放入手写文档。
- 任务进度落在所属工作的现有总览或索引中，不仅留在聊天，也不另建并列进度台账。记录最近更新时间、已完成、正在进行、下一步和实际检查；计划、已实现、未验证与受阻明确区分，静态诊断、构建、测试、运行及视觉验收不能相互代替。
- 每个实质阶段完成、遇到阻塞或停止前更新进度，关键变更继续写入所属修改记录；不记录逐项工具调用流水账。有异议、疑问或尚未确认的部分先不实施，只写入该工作的唯一问题汇总，总览链接过去；继续其他已确认、已授权且可独立推进的事项，不猜测需求。
- 各工作只维护自身总览和问题清单。原始项目只保留工作入口，不复制其他工作进度或开放问题；进度文档更新不触发自动同步，也不扩大代码修改或主动验证授权。

## 工具、编辑与并行

- 优先使用已有 Skill、MCP、IDE、工具和 API。
- 所有工作区开发与验收统一使用 spark、BenchMod、mc mcp、idea mcp、debug，按[项目工具链](../systems/README.md#项目工具链)承担各自环节，不得用其他方式替代对应环节；本要求不统一各工作区端口或环境配置。
- 操作必须显式指定所属工作区真实目录，不根据聊天显示的 cwd 推断归属，不跨工作区写入。项目与公共规范同步必须通过 Git 已提交内容进行三方合并，不用文件复制或整文件覆盖代替；逐段审查冲突并保留分支补充；原始 dev 维护公共地基与协调入口，不代替分支负责人验收。
- 协作仅使用未归档且未被[对话路由](../systems/workspace-layout.md#对话路由)排除的 AI 聊天。保留的旧对话只完成已授权收尾，不派发之后的新任务；轮换后按新ID检索、跟踪和调度，不以标题重新选回旧对话。不检索、恢复或唤醒已归档聊天。
- 工作区统一位于原始仓库 `.workspace/lobecorp_<content>`，由 Git worktree 管理并由原始仓库忽略；现有聊天完成后再为后续任务开新聊天，旧路径兼容链接不得提前移除。详见[工作区目录](../systems/workspace-layout.md)。
- Minecraft MCP 只消费外部仓库构建并提交到 `lib` 的 JAR 和桥接制品；不恢复 `modules/minecraft-mcp` 或源码子项目。升级和隔离见[制品规范](../systems/minecraft-mcp-artifacts.md)。
- 默认使用不抢占实体鼠标或用户实际输入、不干扰当前编辑状态的 MCP/API；被测游戏窗口的最大化与焦点维持按下方测试边界执行。需要并行开发时，优先使用独立工作树、项目目录或 IDE 实例隔离；不得并行修改同一物理文件。后台模拟与GUI测试按[后台输入与测试边界](#后台输入与测试边界)执行。
- 游戏输入、最大化、焦点与实体鼠标边界只维护在[后台输入与测试边界](#后台输入与测试边界)。每轮测试必须截图归档并给出可查看路径；焦点时间线、失败轮及其他证据由所属工作的 BenchMod 与问题清单记录。性能测试中 Spark 从进入测试持续到结束，停止后等待上传链接或输出落盘再关闭客户端；Sodium 保持加载。
- Git 操作优先使用独立扩展 `idea-mcp-expand` 提供的 `git_background`，明确指定当前工作区。当前聊天未列出新工具时，使用原生 `execute_tool` 在相同 `projectPath` 下动态调用；参数写法见[工具调用示例](#后台-git-调用示例)。原生终端 MCP 会激活窗口，不再用于 Git。扩展未加载时，外部后台写入只按已有用户授权执行，不重复申请已给出的授权，不自动重启 IDEA。
- 测试客户端启动后仅对同一实际游戏窗口执行一次非激活最大化；不得在每个场景或每 tick 重复最大化、还原、前置或聚焦。防最小化和后台运行处理必须避免抢焦点、捕获或居中实体鼠标。Photon 等编辑器仍嵌入游戏窗口，按游戏主窗口核对状态。
- 连贯且步骤固定的操作合并为一次 MCP/API 调用或批处理，只在开始、结束及有分支或失败时读取必要状态，避免逐步重复查询。进入新测试世界优先复用开发环境的 Create Test World 快速入口；已在所需世界时直接继续，不重复进入。
- 项目文件只能通过 IDEA 编辑，包括 Java、资源、配置、Gradle 和 Markdown 文档。
- IDEA/MCP 不可用或无法完成编辑时，先说明并等待授权，不自动改用 `apply_patch` 或命令行编辑。
- 每次修改前后，都通过 IDEA/MCP 检查相关文件信息。
- 大型修改前后检查文件内容、错误、警告、语法、引用和 Git 状态；只改数值等极小修改时，只检查相关部分。
- 允许并行处理不同文件，但必须明确文件归属，禁止并行修改同一个文件。
- 保留未修改区域的原文件排版及用户已有暂存、未暂存、未跟踪和编辑器未保存内容；目标文件已有用户修改时，先通过 IDEA/Git 对比，再在同一文件中最小范围合并，不擅自覆盖、重置、暂存、提交或删除。
- 代码格式属于编辑规则，新增代码文件与本次修改行的格式调整已包含在本次编辑范围内，不另行询问格式化授权。完成代码修改后，必须通过
  IDEA 按项目格式处理；新增代码文件可格式化全文件，已有文件仅格式化修改行或明确涉及的类，优先使用行范围，不触及未修改区域。只有用户明确授权的整个项目整理任务才允许按包或项目范围格式化。
- 格式化默认关闭额外的导入优化和成员重排；需要这些操作时，只处理本次明确授权的范围。
- 格式化前确认文件类别与来源。用户提供的 JSON 等资源文件、数据生成输出、第三方文件和二进制资源不纳入自动格式化；需要修改资源内容时保持其原始排版，除非用户明确要求格式化该文件。
- 只修改当前任务明确涉及的内容，不进行无关重构、清理、重命名、格式化或修复。

### 后台输入与测试边界

- 允许不同工作区并行进行非性能游戏测试（逻辑、功能、交互与视觉验证），各自使用独立游戏实例、端口、存档和证据目录；不因另一工作区存在游戏、Debug 或普通 GPU 渲染就要求等待释放。实体输入、焦点和窗口操作仍遵守本节边界，不互相抢占或操作其他实例。性能基准、GPU 写次数计量及同负载 A/B 测试仍须协调独占测量资源，避免其他游戏负载影响测量；并行功能测试结果不得作为性能证据。

2026-11-01 用户明确要求避免测试抢鼠标：本节以不抢实体鼠标、不强制前置和不恢复焦点为准，覆盖此前“保持／恢复焦点”的操作要求。焦点状态只读记录，不能因失焦自动拒绝整轮。

- 允许游戏实例内部的模拟输入、控件或GUI坐标点击、后台定向输入及结构化MCP/API。游戏内部Screen/GUI交互与系统屏幕控制按实际副作用区分，不因工具名称或“模拟／坐标点击”本身一概拒绝。
- 对已核对 PID／窗口句柄的本轮游戏，仅允许一次非激活最大化和不抢焦点的防最小化；不得调用 SetForegroundWindow、glfwFocusWindow 或循环 ShowWindow／restore 维持前台，不得移动、捕获、隐藏或居中系统实体鼠标。不能无副作用实现的能力须报告，不以抢焦点循环代替。
- 不因失焦次数、瞬时 focused 状态或曾失焦一票否决、拒绝测量或丢弃整轮。实际前后台与失焦时间线据实记录，不伪称全程聚焦；性能测量的负载、采样与证据完整性检查继续保留。
- 调用前按接口实现、文档或已有证据核对实体输入及窗口副作用；不能通过实际抢占实体鼠标来试验。本条只调整当前已授权任务的测试方法，不扩大业务、安装、重启或跨工作区写入范围，各工作同步自己的子代理和接续记录。

### 后台 Git 调用示例

若当前聊天的工具列表仍是插件安装前的缓存，可调用原生 `execute_tool`，将 `projectPath` 设为当前已打开的独立 IDEA 项目，`command` 使用 `git_background --arguments '["status","--short"]' --timeoutMs 20000`。该写法已在 2026-10-23 重启后的本机验证；参数数组写成 JSON，不能替换为 Shell 命令或终端入口。项目未打开时先按既有授权打开对应项目，不改用其他工作区上下文。Git 写入、钩子启用与历史改写仍须遵守各自授权，工具可调用不代表获得额外权限。


### 子代理最低推理档位

- 项目内所有子代理只能使用所选模型或代理接口支持的最低推理档位，创建、接续、重新委派及模型变更时均须显式指定；不得因任务复杂、审查或集成需要自行提高。
- 按当前接口实际能力选择最低档，例如支持 none 则使用 none，仅支持 low 起步则使用 low；不把不受支持的档位当成已生效。接口无法设置时如实说明，不声称已指定最低档。
- 本规则仅约束子代理，不修改主对话的推理档位或模型；用户对当前任务的明确指令优先。

通用职责、当前中转型号、调用入口与上下文轮换统一见[DS协作规则版本化快照](ds-collaboration.md)。项目交接位置与索引遵守[代理文档管理](agent-docs.md)，本项目既有轮换与回报授权仅在其原范围有效，不因迁移扩大业务或解除停工。

## 修改规模与收尾

以下任一代码、数据或协议变化都属于大型修改；仅文档整理不因文件数量触发编译或 Data，应检查引用、锚点、规则保留与差异：

- 涉及多个系统；
- 涉及多个文件；
- 重构；
- 包迁移；
- 数据结构变化；
- 网络协议变化。

大型修改完成后，必须通过 IDEA 的运行配置、MCP 和 IDEA 诊断完成：

- 项目编译；
- 数据生成任务（例如 `runData`）；
- 生成资源检查；
- 其他文件中过时调用的检查。

大型修改收尾发现与本次改动无关的既有问题时，只记录并说明需要扩大范围，等待确认，不直接处理。小改动不强制执行上述完整收尾流程。

`runData` 自动生成的文件和目录是只读输出，不允许直接修改，也不允许放入手写内容。生成结果不符合要求时，只修改生成源，再通过 IDEA 重新生成。生成完成后，使用 IDEA/Git 确认只产生预期文件和内容。

新增翻译键时，必须通过 IDEA/MCP 执行数据生成（`runData`），这是对默认不主动运行数据生成规则的明确例外。如果本次任务只新增翻译键，数据生成成功并确认生成结果后即可结束，无须额外执行编译、构建、测试或运行游戏。数据生成失败或受阻时，必须如实报告。

不得把未执行、被中断或被环境阻断的操作报告为成功。IDEA 检查通过的含义是：本次修改不新增相关错误或警告；无关的既有问题只记录，不要求清零。

## 复用已有能力

- 优先复用已知 `lib`、API 和接口。
- 频繁使用或多处共用的逻辑，必须集中提供 API 或工具入口；调用方通过该入口使用，不重复实现判定、状态修改或存储操作。入口应封装实际规则和生命周期，不为已有公共 API 增加无实际职责的重复代理。
- 新增系统、抽象、接口或依赖前，先通过 IDEA/MCP 检索项目源码、已有依赖、当前版本 API 和相关 Skill 文档。
- 如果可以组合已有接口实现需求，必须优先组合，不新增系统。
- 只有确认存在明确能力缺口后，才提出新增方案。
- 引入新的 `lib` 前，必须先说明能力缺口、必要性、影响、版本和维护成本，并得到确认。
- 复用 API 或 `lib` 时，以当前项目锁定版本的 IDEA 解析结果和本地文档为准，不直接套用其他版本示例。
- 过时调用检查以 IDEA 语义引用、Find Usages 和类型解析为主，必要时再使用文本搜索。
- 依赖 JAR、Minecraft 类及类路径源码通过 IDEA/MixinMCP 查询，不用命令行搜索、解压或自行反编译代替已有专用能力。
- 对单例、注册项及可能在注册阶段构造的对象，默认使用 `Supplier` 或等效延迟引用；不得在注册绑定完成前调用 `DeferredHolder#get()`。同时检查构造方法、字段初始化器和静态初始化器中的提前解引用；只有确认仅在游戏运行期创建的对象才直接获取。

## 版本与验证边界

- 当前项目版本以 IDEA 解析结果、项目配置和已锁定依赖为准。
- 有意义的更改执行任务范围内最小相关验证，复用条件未变的有效结果；静态诊断、构建、Data、运行与视觉验收分别报告。纯文档修改检查引用、锚点与差异，不因此运行构建、Data 或游戏。
- 大型代码修改按照本文件的收尾流程执行，并只报告实际完成的检查。必要验证不自动授权安装插件、重启 IDE、迁移环境或新增无关游戏测试。
- 修改完成后保留用户已有的暂存、未暂存和未跟踪工作，不擅自重置、覆盖、暂存、提交或删除。
- 每次任务修改完成后都必须创建 Git 提交，包含本次修改及同步文档；仅暂存和提交本次授权内容，保留用户其他修改及暂存状态。提交受阻时如实报告原因，不得将未提交报告为已完成提交。
- Git 提交标题和正文只能使用中文，不使用英文类型前缀、英文说明或默认英文合并消息。历史改写只处理用户明确授权的未推送提交，不自动推送或改写已发布历史。

## 测试场景保护
