# 群体事件与深夜清扫

2026-10-23 整理：本文只保留当前玩法、API、命令和配置契约；固定线路与 GPU 细节见[渲染契约](horde-rendering-implementation.md)，所有未解决问题统一见[Horde 问题汇总](horde-issues.md)。

## 当前行为

当前源码已改为固定线路、显式纵横间距和 GPU 移动、让行、骨骼动画。密度、种子、动态线路修订、图片图集、LOD 渐变与主体射线遮挡已移除。默认数量和范围均为 -1；原有配置文件不会被默认值变更强制覆盖。

完整实现、原版区段光场、资源生命周期与待验收边界见[当前渲染实现](horde-rendering-implementation.md)。光照在让行后实际位置按实体眼高采样，不再整段共享一个亮度。真实参战调度与实体流程保留。

存档使用新标识 horde_events_gpu_v1，不恢复或转换旧活动事件，旧文件不删除。新命令为 `/lobecorp horde start <profile> <from> <to> [ticks] [width] [waypoints]`，不再接受 seed 参数。全部线路高度准备完成后才启动；客户端等待完整线路再显示。

本轮未启动游戏或性能验收，编译和 Data 状态在修改记录单独列出。以下内容均为旧实现的历史证据，不是当前行为。

## 架构与入口

通用入口为 `HordeEvents.start/stop/snapshot`，事件定义实现 `IHordeEventProfile`。首个定义为 `lobecorp:midnight_cleanup`（深夜清扫）。服务器只持有事件、线路和正常参战关系；虚拟浪潮由客户端按种子和统一时间推算，不创建隐藏 Entity，也不保存逐个虚拟单位。

事件在完整线路高度准备完成后开始，默认生成6000逻辑刻、宽128格，128格宽时每平方格1个影像作为密集基准。线路自动形成平滑闭环，每个虚拟单位只跑一圈；没有途经点时由起终点形成两条平行路段并闭合，有途经点则依输入顺序平滑闭合。到达同处的出口后离场，不重复绕圈。奔跑速度取事件定义并持久化，清道夫按既有移动属性、奔跑倍率及原版平地摩擦换算稳定速度；生成时长不再改变奔跑速度。收尾时间为最后一批跑完一圈所需时间，替代此前与生成阶段等长的预估。入口和出口均按fadeTicks以透明度平滑渐变。未加载区块不暂停时间也不被强加载，关服期间不推进；已有事件保留线路和规则快照。无法绕行时允许虚拟影像沿粗路线穿行，正常实体出生仍检查安全与粗略可达性。

虚拟分布与正常战斗独立。创建或死亡一个正常清道夫不隐藏、移除或扣除某个虚拟编号。普通清道夫不带事件附件，不受事件规则影响。

## 战斗调度

各目标初始配额1，首次攻击技能启动或受到分配目标的有效伤害后计时，每100刻增援1，最多3。参与者死亡立即提高一级并重置计时，预约创建请求占名额。已有单位因目标人数减少转派时可以超过3，不为恢复配额强制减员，超额时不新增。

同维度同阵营同类型事件共享配额，先覆盖首人再分配第二、第三人。正常参与者锁定分配目标，第三方攻击仍正常承伤。战斗区域融合后共享转派范围，拆分保留已有分配。没有区域内可分配目标才淡出移除。

正常实体从目标的浪潮来向一侧安全创建，不使用某个虚拟影像的位置。每维度共享100个正常实体软预算、每刻最多2次成功创建和出生工作预算。无法接敌超时和重试冷却默认各100刻；当前排队计时偏差统一记录在[问题汇总](horde-issues.md)。连续出界40刻解除，追击范围只覆盖当前浪潮路段及余量。

淡入淡出均默认5刻。淡入仅影响表现；淡出立即取消技能、关闭AI、碰撞与承伤、释放名额，结束后移除。事件截止取消排队、禁止新增参战，并让存活参与者退出。正常死亡、掉落和尸体流程保留，事件尸体禁止复原。立即清除也保留已有尸体。

事件单位不允许指挥家登记、收编或控制；检查覆盖服务端目录、实际控制资格和进入世界路径。区块卸载释放存活单位的名额，不作为死亡增援；正常关服保留有效分配。

## 命令

仅管理员可使用：

```text
/lobecorp horde start lobecorp:midnight_cleanup <起点x y z> <终点x y z>
/lobecorp horde start lobecorp:midnight_cleanup <起点> <终点> <ticks> <width> [x,y,z;x,y,z]
/lobecorp horde list
/lobecorp horde stop <event-uuid>
/lobecorp horde clear <event-uuid>
/lobecorp horde stats
```

`stop`进入收尾，`clear`立即结束；均不清理已有尸体。API支持途经点及时长、宽度覆盖，不接受种子；没有自然触发或事件编辑器。

## 配置与同步边界

服务端 `lobecorp-horde-events.toml` 保存生成、配额、时间和共享工作预算；事件启动时固定规则快照。客户端 `lobecorp-horde-visuals.toml` 保存显示数量、范围、聚合脚步、扬尘与调试开关；当前没有旧 LOW/MEDIUM/HIGH/CUSTOM、LOD 或自动降级配置。

`maximumVisible` 默认 -1，0 关闭主体显示；`rangeChunks` 默认 -1，跟随有效视野距离，显式范围不超过该距离。`debugRanges` 提供线路和本地范围线框，仅是显示辅助，不证明目标或出生请求已建立。

客户端接收完整线路后显示；正常实体沿用原版追踪和现有附件同步，虚拟事件使用独立状态与快照请求。服务端不发送客户端显示区域，不新增目标 UUID 同步。

具体渲染和资源生命周期见[渲染契约](horde-rendering-implementation.md)；历史数据、备份与适用范围见[基准说明](benchmod.md)，全部未完成问题见[问题汇总](horde-issues.md)。
