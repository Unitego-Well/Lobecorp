### 修正后的几何与边界

记 q=choice×across，f=smoothstep(0,0.5,radius)，M=1.5。候选幅度 A=min(16,max(0,radius+M−abs(across)))×f×(1−max(0,sign(q)))；q>0 的圆不产生朝向自己的推力。近侧容量为 mix(16,clamp(q−radius−M,0,16),max(0,sign(q))×f)。成熟圆的容量沿局部直线不依赖 station，不贡献静态斜率。

左右分别取所有圆候选的最大幅度作为整段可容纳性检查，再与该侧所有近侧容量的最小值比较；完整幅度超容量则不选择该侧，不能把完整绕行截成穿核心的半次横移。选定侧仍使用最大包络和获胜解析导数；三次 ramp、提前长度与 0.7 分割速度上界不变。对成熟圆与可容纳的局部直线通道，平台前已完成横移；对面的圆由近侧容量保护，生成候选的圆由完整幅度保护，均含 ±1.5 sway 余量。

能力边界具体为：通道筛选是沿该局部直线的保守横向容量，纵向分离的多个圆也可能互相限制；不做多段换侧通道寻优。两侧均不可用时保留原解析横向运动，因此不能保证原路线本来穿圆时被解出，但不会采用半次横移宣称成功。半径小于 0.5 的 fade 阶段、动态变径/移动导致的通道可容纳性和选侧变化，不保证聚合净空或完整 C0 动态切换；单圆幅度及容量权重归零连续，静态进入/退出仍连续。16 上限与超能力圆仍不保证净空。弯曲路线、地形流、端点裁剪、真实 GLSL float 和游戏视觉继续未验收。

环境粒子只在客户端生成，默认每tick尝试近3、中2、远1个不同区域，区域格分别8/16/32，距离带为0～8、8～16、16～32格，同时受particleRange默认24限制；每区域烟雾/碎屑/刀光分别为2/4/2、1/2/1、1/1/1。候选从实际提交行列中随机采样，需处于潮头尾内、已加载、视锥可见且无遮挡，避开目标安全包围及模型半径；清扫提示最多额外补一处。每粒还按最终出生位置重复距离、视锥和准确射线检查。原版粒子引擎仍管理出生筛选、生命周期和绘制，不宣称它是全GPU粒子模拟，也不替换粒子资源或改原版粒子设置。

本轮13份Java、9份GLSL错误诊断均0错误，编译及23项无游戏回归通过，Data退出0且29份生成文件哈希不变。用户随后取消实机测试，因此没有GPU硬件编译、光影性能、粒子画面或抖动验收。统计口径见[BenchMod](benchmod.md)，剩余问题仅见[问题汇总](horde-issues.md)。

## 数据与职责

- 服务端保留事件、固定线路、真实参战分配和目标分组，只负责真实生物的生成与参战调度，不参与客户端显示分割。虚拟单位不创建 Entity，不参与命中、AI 或实体生成判断。
- 默认纵横间距各1.8格；列数按宽度和横向间距居中排列。GPU按稳定行列相位派生有界纵向速度变化及左右摆动，不创建CPU逐单位运动状态。
- 事件开始时准备粗高度：横向间隔不超过16格，纵向每16个不超过1格的中心线采样节点取一行，保留尾行，其余行按弧长插值。新事件覆盖路线宽度、最大64格横移及1.5格摆动，客户端按节点实际采样宽度编码；缺失区块暂用输入高度并排队校正，允许创建且不强制加载；严格采样器重载仍可报告缺失，用于隔离基准准备。
- 中心线XZ与弧长固定；按输入顺序构造开放多段，不自动闭合。线路锚点使用向心 Catmull-Rom 和自适应弧长采样，转角处使用更密的样本。成功的Level.setBlock更新按16×16空间块合并脏标记，每事件每tick最多刷新两个块；未加载块轮转等待。仅重采粗样本，再插值相邻节点并提升变化节点版本，预算内增量同步；不重新寻路。
- 客户端必须接收全部节点后才显示；reset header先完整解析再替换，失败限流请求快照，维度卸载清理本地事件与GPU数据。线路同步保留扫描进度，多事件按逻辑刻轮转。客户端生成弧长查找表、平滑方向和保守空间块。GPU 在查找表基础上定位原始路段，插值位置和横向高度。
- 客户端每tick统一收集玩家模拟距离内Mob与本地玩家，不执行线路走廊过滤或距离错峰。CPU提交原始整数xyz与xyz尺寸以及稳定身份代次；按最新需求取体型三倍余量与至少3格水平外扩，再按1格取整，Y不扩大，原8/16/32不再撑大单体缺口；目标变化或旧端点收敛才提升版本。GPU计算流场绕行、随机运动、朝向与烘焙帧动画。真实生成仍使用服务端profile资格，不新增目标UUID同步。绘制批次容量65536不等于总数量上限。
- 默认 maximumVisible=-1、rangeChunks=-1；已有配置值不被默认值覆盖。每16个线路小段按横向16格组合绘制块，包围盒合并全部小段。高度变化只替换受影响高度纹理行与相邻块边界。有上限时只按块距离和稳定顺序分配预算，不进行逐单位候选堆或排序。原版F3+B或浪潮调试条目通过Gizmo绘制青色线路范围、黄色本地范围及橙色整数分割区域。
- 新存档标识为 `lobecorp:horde_events_gpu_v1`，事件 format=1；不读取或转换旧活动事件，不删除旧存档文件。命令移除 seed 参数。

## 战斗区域与平滑让行

每个目标提交六个32位整数与稳定身份，GPU持续保存阻尼状态；CPU不求插值。出现从中心零半径展开，退场保留原中心并缩小，RGBA8按原始位模式运输并重建整数，先整数原点相减再转局部浮点。GPU完成区域影响筛选与势流位移，不恢复CPU逐绘制块影响列表。CPU既有静态模型、线路、光照资源准备仍保留，严格GPU范围的剩余边界见问题总表。事件来源附件在真实实体加入世界前设置且具有同步编解码器，客户端Mob筛选排除成员的独立缺口；成员仅能扩展已有目标战斗包围，普通来源清道夫仍保留。

GPU使用连续软方向势流绕过区域，重叠影响按同侧连续上包络合并，不再通过硬sign或最大影响分支切换，最大横向偏移64格；空间块保守边界相应扩展。目标Y区间只与当前地面到实际实体高度重叠时影响浪潮，垂直离层半格后影响归零；实际高度随事件头同步。地形先复用粗高度场，对高于相邻通道的采样障碍使用与分割同源的GPU持续阻尼绕行，再施加区域约束，不把它当作精确方块碰撞。

按稳定全局行列派生个体随机相位、频率与幅度，纵向扰动最大±1.8格，横向摆动最大±1.5格；基础速度来源与数值不变，只叠加连续随机加减速，低速时缩放纵向扰动以免反向，不保存CPU逐单位状态。区域中心/半尺寸及速度由GPU持续更新；个体位置与方向保存在稳定编号GPU历史，按最短弧阻尼转向，不保存CPU逐单位状态。新算法实机平滑度未验收，本次不启动游戏。

服务端目标发现、成员存活/目标检查、区域分组和生成请求改为每tick处理，不按区域轮转；出生安全检查仍受显式工作预算约束。目标与清理只扫描玩家模拟距离的已加载实体，战斗保护和清理判定属于服务端玩法，不能交给客户端删除实体。

这不是精确路径搜索或碰撞求解。薄墙、屋檐、多楼层、重叠区域和粗采样遗漏仍需实机确认；不伪称已解决全部穿插。

## 模型和动画

HordeMeshCache 从现有模型及 run 循环提取静态几何、骨骼归属和父链，在完整原始动画周期内均匀取配置数量的样本（默认4帧、可调4～20），烘焙成各帧静态顶点数据：每顶点每帧保存模型空间位置和法线，共 6 个 float。每帧使用 GeckoLib 的 `BoneSnapshot`、`LcAnimationBoneAdapter` 和 `RenderUtil.prepMatrixForBone` 骨骼链/`GeoCube.render` 生成顶点，父链、枢轴、基础旋转、缩放和法线都由 GeckoLib 处理，不再自己拼骨骼矩阵，也不使用 `transformToBone` 的额外枢轴平移。`BoneSnapshot`、帧捕获器和 `PoseStack` 只创建一次并在帧循环内复用，结果写入一次分配好的帧数组后缓存。GPU 按每单位相位选择帧号并直接读取该帧位置/法线，不再执行骨骼变换或插值；帧号取整后循环切换。用户已确认烘焙朝向和动画正常；更多模型、场景和性能仍需验收。

模型和动画数据共享，不创建逐个动画控制器，不写共享 GeoBone 状态，不执行动画事件。烘焙期会临时挂载并清理每帧 `BoneSnapshot`，只在客户端资源准备线程使用。相位由行列公式决定。数据纹理使用 RGBA8 保存 float 的原始位模式，整数纹素读取后解码，不把数据当图片做线性过滤。

资源准备失败记录事件 ID 和异常，停止该事件虚拟显示；没有旧渲染回退。资源代际变化允许重新准备。骨骼父链最多 64 层，超限明确拒绝。

## 位置正确的原版光照

本版替代原计划的整块共享亮度：

1. CPU 按可见块收集已加载的 16×16×16 光照区段。
2. 读取原版 LevelLightEngine 的 BLOCK/SKY 压缩区段数据，每 5 tick 比较一次，仅上传变化区段。缺少天空光 DataLayer 时按原版竖列回退采样，不能当作零。
3. GPU 在让行后的最终单位位置，加上事件定义中实体尺寸的 eyeHeight，取对应方块及区段。
4. GPU 通过区段索引取两层 0—15 亮度，按原版 sample_lightmap 规则读取当前 lightmap。
5. 使用原版实体方向光照和变形后的法线，合成原贴图及 glowmask，再应用雾。

依据：EntityRenderer.getPackedLightCoords 使用 Entity.getLightProbePosition，默认是 getEyePosition；普通非燃烧实体的 block/sky 取值来自对应 LightLayer。虚拟单位没有燃烧实体状态，不额外强制满亮。

区段只按区域共享数据，不按单位上传或读回位置。光照更新最多有 5 tick 延迟；不在当前已加载区段索引中的单位不显示，不沿用卸载前亮度，也不伪造天空满亮。没有复制动态手持光源、光影包专用材质或阴影能力。

## 绘制与生命周期

2026-10-23：运动缓存按总实例不超过65536的组依次处理，所有组继续绘制，不自动减量；光场容量不足时进一步拆组并回收非当前组槽位。共享GPU资源异常清理后按1—5秒退避重新准备，不再把同帧全部事件永久标为failed。单事件模型资源错误仍隔离处理，实际设备/着色器验收见问题汇总。

运动缓存使用每实例8个原始位模式值：xyz、角度、打包亮度、sin/cos及帧起点；不降低位置精度。区域数据以六个整数的原始位模式存入数组并按容量复用纹理，光场区段集合/排序按逻辑刻或块选择变化刷新。

只保留单一三维表示并写深度，模型LOD使用显式配置；不做主体整模透明淡入、双表示渐变、CPU光栅图集或CPU射线遮挡。CPU保留既有静态空间块距离和视锥提取，不再逐帧检查区块加载；未加载位置由GPU光照有效性剔除，墙后像素由深度测试处理。

2026-10-24新增Iris转接：世界渲染期间读取实际ENTITY_CUTOUT/EYES格式，原版36字节写9个字，Iris扩展56字节写14个字；扩展的实体标识、中间UV和切线同样由GPU生成。RGBA8附件直接复制到GPU顶点缓冲，不执行CPU映射或逐单位运动计算，再交已有Iris映射的原版ENTITY_CUTOUT/EYES。位置和UV保持float32，法线/切线遵守原版字节输入；单工作集约32MiB，拆批不减少总数，gpuCopy统计每帧GPU内复制字节。未开启光影时保留实例化快路径。当前Complementary实机已确认本体可见及夜间遮罩发光；10000实例GPU均值67.89ms的性能失败集中见H24，不承诺完整光影兼容。

绘制位于AfterOpaqueFeatures，使用当前颜色、深度输出覆盖目标，普通深度LESS_EQUAL并写入深度，跳过Iris阴影pass，按API报告选择普通或反向深度。石墙遮挡已在无光影包场景对照截图；透明排序不在本轮范围。使用原版光照并不等于进入光影包 GBuffer；完整光影外观及后处理仍需实际验证，不承诺任意包兼容。

所有纹理准备、缓冲上传及索引扩容在 RenderPass 前完成。无计算着色器、原生 OpenGL 旁路或同步读回。事件结束释放线路和区域 GPU 数据；世界退出和资源重载释放共享模型、动画、光场和参数缓冲。TextureManager 持有的原始贴图只借用。

脚步声与粒子消费可见空间块中心摘要，不依赖逐单位显示列表。粒子去掉dustPerTick预算，改particleIntervalTicks默认1，每次各发射一粒篝火烟雾、方块碎屑和原有清道夫刀光，默认玩家24格内且通过视锥、加载和方块遮挡筛选；实际路径清扫提示通过原版粒子发射器协议通知并优先消费，按格合并且一秒后过期。原版粒子的筛选与生命周期仍在CPU，不把GPU绘制等同于全GPU模拟；主浪潮分割与运动仍由GPU执行。少量聚合声源继续保留原有低频声音遮挡检测，不参与主体可见性。
