## 路线与纹理

- `HordeClient.ClientEvent.refine` 在本轮节点更新完成后，按脏节点和脏区块组去重：相邻方向、每个区块组只重建一次，区块列表只发布一次。
- `HordeGpuRenderer.EventData` 合并同一高度纹理内连续的脏节点；路线与高度纹理仍独立持有。
- `HordeDataTexture` 先写完 CPU 像素，再提交首个非整行、中间整行矩形、末尾非整行，保持原始 32 位字和覆盖范围。
- `HordeNearTerrain` 保留采样预算、轮换、参数与失效规则，按原始浮点位比较高度、通行标志和世界坐标；同值块不上传，变化区间同 tick 上传。

## 附着增量同步

- 协议版本为 **30**。载荷字段不变，但客户端物品时钟和服务端发送基线配套更新，不能与旧处理逻辑混用。
- 每连接保留附着快照与物品描述。实际状态相同时不重发；物品采样时间戳本身不构成内容变化。
- 新增、变换、锚点、修订、物品组件、播放起止、移除和重新可见仍当刻同步。初次或换维度发送完整快照。
- 本次更新的绑定没有物品描述仍表示解除描述；物品独立变化也必须带绑定更新。
- 客户端用连接最新服务端时钟和对应本地收包时刻推进物品动画，不组合未更新物品的旧采样时间与新收包时刻。无新包时继续推算时间。
- 动画锚点可见性复用本次玩家可见动画 ID 集合；实体锚点和渲染锚点检查仍保留。

## 编码与查询

- 动画完整内容按包含资源 ID 与原始内容的版本哈希共享编码和分块，每连接的已发送版本集合仍独立。
- 编码缓存最多 64 项、8 MiB。单项超额仍正常发送但不缓存；淘汰只导致重编码，不影响发送资格。服务端停止时清理。
- 字节数组防御复制、发送字节、分块大小、顺序和发送时点不变。
- Horde 每玩家每次同步复用路线投影，供订阅、排序和发送中心使用；不跨轮次缓存。
- 出生请求在本次调度内复用各维度存活数，尝试创建实体前失效，后续请求重新统计。原配额、暂停和出生工作预算不变。
