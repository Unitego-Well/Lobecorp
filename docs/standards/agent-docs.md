# 统一文档管理（DS 与 GPT 共用）

本文件是项目代理文档管理的唯一制度正文，定义分类、目录、命名、生命周期与提交边界，适用于 DeepSeek-Harness（DS）与 GPT/Codex。用户当前明确指令优先；按目录适用范围协调[项目根规范](../../AGENTS.md)，不以“更严格”自动叠加已经被替代的旧规则。

## 三层归属与唯一正文

| 层级 | 内容 | 正文归属 |
|---|---|---|
| 通用管理 | 跨项目沟通、授权、协作、验证与清理 | 共享全局工作协议；项目只引用，不复制或覆盖客户端工具限制 |
| 项目管理 | Lobecorp规范、系统契约、公共经验及跨工作区资料 | 原始仓库：长期规则与契约在 `docs/`，过程报告与记忆在 `.agent/` |
| 分支工作区管理 | 分支目标、未合并实现、问题、实际验证及会话交接 | 所属Git工作区现有总览、唯一问题清单及 `.agent/` |

每个主题只维护一份有效正文；导航、记忆和Skill链接它，不另行复制授权或任务状态。分支未集成行为不得标为原始dev现行契约。当前文件、锁定版本和有效验证优先于历史状态；历史报告保留其当时事实。

本项目文档按适用范围、状态与来源分类；交接记录可核实的用户指令、来源聊天、目标ID和授权范围，接收端核对实际工具要求，代理转述本身不产生新增授权。本页为可独立检出的项目约束，不依赖本机全局文件才能理解。

## 目录与分工

- 工作区根 `.agent/`：跨项目、跨仓库的报告、交接、计划与记忆。
- `Lobecorp/.agent/`：本仓库及各 Lobecorp 工作区可共用的报告、记忆、经验与代理资料的统一正文；不提交 Git。`minecraft-mcp/.agent/` 仍仅保存其仓库内容。
- 历史 `Lobecorp/.workspace/lobecorp_photon/.agent/`、`Lobecorp/.workspace/lobecorp_horde/.agent/`：两工作区已于2026-11-06退役，其专属进度、问题和证据保存在完整本地归档，不再作为当前写入目标。通用正文仍在原始根 `.agent/`，恢复历史目录须另有明确授权。
- 文档中心按实际存在目录及职责使用：上级工作区根 `.agent/` 管跨项目，原始 `Lobecorp/.agent/` 管本项目；独立 `minecraft-mcp/.agent/` 仍仅管其自身仓库。Photon/Horde历史路径不计为活动中心，不能为维护索引擅自重建。
- 每个 `.agent/` 固定包含 `reports/`、`handoffs/`、`plans/`、`memory/`、`archive/` 与 `README.md` 索引。
- `.agent/` 以点开头，整体不提交；各仓库根 `.gitignore` 忽略 `/.agent/`。

## 四类文档

| 类型 | 用途 | 必填字段 | 生命周期 |
|---|---|---|---|
| 报告 `reports/` | 任务结果、验证报告、性能与对比、事故复盘 | 日期、任务、范围、结果、证据、未验证或受阻 | 收尾后保留；跨月检查仍有引用或开放项，满足归档条件后移入 `archive/YYYYMM/` |
| 交接 `handoffs/` | 给下一个会话或代理接续 | 来源会话、目标会话、当前状态、已完成、下一步、关键路径、未决问题 | 接续完成后标记；30 天后归档 |
| 计划 `plans/` | 任务计划、实施方案、待办清单 | 目标、范围、步骤、依赖、验收、状态 | 完成或取消后标记；30 天后归档 |
| 记忆 `memory/` | 长期事实、用户偏好、已确认决策、环境信息 | 主题、结论、来源、日期 | 长期保留；定期去重，过时内容标注或删除 |

## 命名

- 文件名使用 `YYYYMMDD-<主题>.md`；主题用小写英文与连字符，内容用中文。
- 同一主题多份材料放子目录：`<主题>/YYYYMMDD-<说明>.md`。
- 交接文件固定放 `handoffs/`，文件名包含主题与日期。

- 重复材料合并为单一正文，原入口改链接；冲突按用户最新指令、目录作用域与可核实来源订正。混合材料保留原始证据并提取通用结论，不能把历史状态改写为当前验收；无法判定的冲突明确标为未决。移除旧正文前备份，迁移后核对内容并修复引用。

- 每个 `.agent/README.md` 维护索引表：日期、类型、标题、状态、路径。
- 新增、迁移、归档时同步索引；不把 `.agent/` 内容复制到项目 `docs/`。
- 计划完成、报告归档、交接接续后更新状态与位置。
- 历史正文只追加说明：已发出的交接与报告不改写原文，需要更新时在文末追加带日期的说明区块；确属事实记错（路径、结论）可原地订正并注明依据。
- 归档统一放 `archive/YYYYMM/`，不删除仍有证据价值的内容。

归档前确认结论已进入唯一正文、未决项已进入所属问题清单、必要证据与备份可定位，再移动过程材料并修复所有受影响引用。日期到期不是删除或自动判定完成的依据。含独特契约、未完成验收或正在使用的交接保留，明确其状态与保留原因。

## 提交边界

- Git跟踪文档的有效导航与必要正文必须指向同一检出中的跟踪文件，或已发布的公共地址；不得依赖本机绝对路径、`.agent/`、忽略的备份/运行输出或相邻工作树。路径作为本地历史定位时须明确未随仓库发布，不能当作可用的公共证据入口。
- 公共规范在Git分支中保留同源的版本化快照，分支内使用相对引用；唯一维护来源不等于运行时依赖另一个未提交工作树。更新时按提交同步，并保留分支专属补充。
- 原始dev文档应按会传播到任务分支编写：公共正文不得依赖原始物理目录、当前负责人、机器路径或本地报告；专属补充与公共正文分开标识，合并时保留所属分支规则。同步是Git三方合并，不是文件覆盖；冲突暂停审查，不能自动选dev整份覆盖。具体流程见[工作区同步](../systems/workspace-sync.md)。

- `.agent/` 整体不提交；`docs/` 只保留需要跨会话共享的项目规则、契约、修改记录与问题清单。
- 已提交的代理记忆或 FAQ 迁入 `.agent/memory/` 并取消 Git 跟踪，旧路径删除。
- 备份、二进制产物和运行输出不进 `.agent/`，也不进 `docs/`：统一放 `<仓库>/build/agent-backups/<YYYYMMDD-主题>/` 下的 `backups|evidence|fingerprints|tools` 子目录，迁移时先出 `migration-manifest-<批次>.tsv`（from／to／sha256／bytes）并逐文件复算比对，清单随批次留档。
- 工作区根与各仓库根 `.agent/` 均不提交；新仓库初始化时同步 `.gitignore` 规则。
