# Lobecorp Java 版冒烟测试

范围：本项目；维护：2026-11-10。状态：流程已编写，尚未实机演练。

## 输入与入口

输入为当前工作区、本次改动、待验证行为与本轮授权范围。授权遵循项目 [AGENTS](../../../AGENTS.md) 的共享协议入口，读取技能本身不授权构建或游戏操作。

先读 [测试入口](../../../docs/tooling/testing.md)、[游戏测试与场景保护](../../../docs/standards/workflow/game-testing.md)，再从 [系统索引](../../../docs/systems/README.md) 只选择受影响契约。需要 MCP 操作时读 [结构化操控](../../../docs/tooling/minecraft-mcp/minecraft-mcp-controls.md)；连接和制品问题按 [MCP 手册](../../../docs/tooling/minecraft-mcp/README.md) 选择正文。

适用：“对本次实体改动做冒烟测试”“验证当前版本能否启动、进世界并完成关键操作”，以及当前游戏改动运行验证语境中的“跑一下看看”“进游戏检查一下”“测一下能不能正常玩”“验证这次改动有没有问题”。用户无需说出技能名。先根据上下文识别对象；“跑一下”明确指编译、脚本或单测时不切换成游戏测试。表达用于定位技能，不扩大本轮授权。

不适用：仅研究测试概念、仅编译、静态代码检查、完整玩法验收、性能优化或长时间稳定性测试。

## 1. 建立本轮身份

记录分支、HEAD、相关未提交修改、实际构建产物、Java／Minecraft／NeoForge 版本，以及游戏 PID、MCP 端口和 gameDir；不将文档中的历史端口、版本当作本轮值。既有进程只有确认加载了本次产物后才能验收；无法确认则标记受阻，不借用其他工作区实例。

预检查按改动选择最小范围，并在测试入口核对命令副作用。编译、JUnit、Data、游戏与性能分别记录；不将 build、check 或 verifyBench* 当作无游戏的通用预检查。构建完成不能作为运行通过。

## 2. 制定最小矩阵

每项先确定预期、观察方法、超时和清理动作。基础路径为：启动到主菜单 → 进入独立测试世界 → 基础交互 → 本次改动关键路径 → 保存退出；涉及持久化或保存风险时重新进入验证。

| 改动 | 追加检查 |
|---|---|
| 实体、AI、技能 | 生成指定实体，触发关键行为，回读结果并清理本轮对象 |
| Encounter、Horde | 核对真实入口与核心状态转换；直接生成对象仅证明对应局部路径 |
| HUD、动画、特效 | 检查实际显示、关键阶段及结束清理，保存对应画面；特效遵循项目透视要求 |
| 配置、存档 | 检查读取、生效、保存与重新加载，核对迁移或默认值变化 |
| 网络、服务端边界 | 在获授权的独立服务端环境追加客户端连接与受影响交互 |
| Bench 相关 | 仅在现有场景确实匹配目标且获授权时运行；先读 [BenchMod](../../../docs/tooling/benchmod.md) 对应章节并核对源码 |

不默认运行重负载或性能矩阵，不把现有 Bench 场景通过扩展为完整玩法通过。需要新场景时遵循场景保护正文，不能缩短或改写旧场景语义来制造冒烟结果。

## 3. 准备隔离环境

为本轮建立独立批次的 gameDir、世界、端口和证据目录。需要用户配置时只复制明确选定内容，记录来源；不改原 run/client 的 Options、存档或光影配置。核对实际启动参数、工作目录及加载的 Mod；仅改变 cwd 不能证明 gameDir 已隔离。现有启动配置不能安全覆盖目录时，报告具体缺口，不直接启动到原世界。

普通客户端与 Bench 的 source set、运行类路径和 MCP 加载方式分别核对，不假定每个 Bench 都提供 MCP。使用当前实际可用的 IDEA 配置；缺少能力时说明，不擅自安装或改造工具链。

## 4. 运行与观察

核对 PID／窗口后，按游戏测试正文一次非激活最大化，使用 MCP 查询、结构化操作或游戏内模拟输入。窗口、焦点、实体鼠标和 Options 边界以该正文为准；功能冒烟不自行升级为性能测量。

写操作后回读实际状态，必要时等待有界的跨 tick 结果。accepted、命令成功或截图成功不等于行为符合预期。超时后先查询状态，不盲目重发可能已执行的操作。直接设置状态不能代替对真实玩家触发路径的检查；报告注明实际走过的路径。

## 5. 日志与判定

保留完整启动日志，标记测试时间段，检查新增异常、资源加载失败、Mixin／注册错误及退出异常。已知告警记录依据和影响，不静默过滤，也不将所有 WARN 自动判为失败。

每项采用 PASS（观察到预期）、FAIL（观察到违背预期）、BLOCKED（环境或工具阻止验证）、NOT_RUN（未执行）。声明不适用的检查需说明理由，不能用不适用隐藏必选路径。必选项存在 FAIL、BLOCKED 或 NOT_RUN 时，不得宣称本轮通过；可报告已经通过的局部项目。

截图只能证明对应时刻和视角；运行通过不代表完整玩法、多人、完整视觉或性能验收。工具不可用时如实保留证据缺口。

## 6. 收尾与交付

释放本轮持续输入，退出接管并回读状态；具体恢复要求见 [后台控制技能](../lobecorp-mcp-background-control/SKILL.md)。只清理本轮创建且可确认归属的对象和进程，不误关用户既有游戏。保存失败日志、未完成状态及清理失败项。

报告使用 [结果模板](references/report-template.md)，按 [代理文档归属](../../../docs/standards/documentation/agent-docs.md) 保存；证据使用独立批次，不能覆盖旧轮次。没有报告写入授权时在回复中提供结果。模板仅在准备或交付本轮结果时读取，不因加载技能自动创建文件。
