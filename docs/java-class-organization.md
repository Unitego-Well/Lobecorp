## 已发现的结构问题

1. 实体实现已按类别迁移到 `entity` 下的 `abnormalitie`、`ordeal` 和 `projectile` 等包；后续新增实体应直接放入对应类别包。
2. 事件模型同时存在 `event` 与 `events` 包；`event` 只放事件定义，自动订阅入口集中在 `events`，两者按职责保留。
3. 实体技能使用 `entity_skill`，实体状态使用 `entity_state`，技能和状态的注册分别位于 `registry.entity_skill` 与 `registry.entity_state`；这是运行域和注册域的固定边界。
4. 通用工具位于 `util`、`entity.util`、`generator.util` 等多个位置；工具类名称统一采用 `*Util`，能力接口保留能力语义，不改名为工具类。
5. `conductor` 原先所有职责集中在单一包；现已按能力、数据、控制、世界、生命周期和工具拆分，Payload 归入 `network`。
6. `registry` 中同时存在注册器、注册辅助逻辑和客户端注册逻辑；需要保持注册定义与运行时业务分离。
7. `client.conductor` 已形成独立客户端域，但客户端事件、渲染注册和实体调试仍分布在多个包中。
8. Mixin 文件按目标对象分组，但业务分支仍可能反向依赖 Mixin 内部实现；应只保留最小注入桥接。

## 历史阶段的目标职责边界

- `api`：跨域公开契约、能力接口和扩展点，不保存运行状态。
- `entity`：实体实现、AI、导航和实体专属客户端表现；实体类别与客户端渲染分层。
- `entity_skill`：技能定义、请求、结果、运行实例、效果和技能适配；技能数值归注册属性，运行实例不写入世界存档。
- `conductor`：指挥家领域数据、控制、移动、队形、远程目录和服务端命令；通过能力和 `*Util` 入口访问附件。
- `hitbox`：命中框几何、生命周期、效果应用和调试快照；不承担技能状态机。
- `animation`：动画层和动画状态表现；不执行 AI 或伤害逻辑。
- `registry`：只负责 NeoForge 注册对象和注册生命周期，不放实体运行逻辑。
- `events`：唯一自动事件订阅入口，按功能域分发；业务处理保留在所属域类。
- `network`：载荷定义、编解码和协议分发；不直接修改实体内部状态而绕过服务端校验。
- `client`：客户端会话、HUD、镜头、输入和缓存；不保存服务端权威数据。
- `mixin`：原版桥接和必要拦截；通过能力或域工具调用业务代码，不复制业务状态机。
- `util`：无状态、可复用的 `*Util` 方法；不作为隐式服务容器，不持有实体、世界或渲染对象。

## 注释和通用文档

- 新增或移动的类用一句话说明职责和边界；公共方法只说明参数、返回值和副作用。
- 注释只写业务原因、生命周期约束和版本敏感点，不记录开发过程，也不重复显而易见的代码。
- 业务常量、资源 ID 和规则参数集中管理；注释描述用途，不把散落数值当作文档。
- 每个整理批次同时更新 `java-architecture.md` 和本记录的状态；文档中的计划不能代替 IDEA 当前代码索引。

### 阶段一：文档和清单（已完成）

- 固化类数量、包分布、当前职责和已确认边界。
- 记录每次迁移的来源、目标和 IDEA 引用检查结果。

### 阶段二：职责和调用边界（首批完成）

- 先处理直接跨域访问：附件、能力、技能状态、世界目录和客户端快照。
- 业务调用统一经过能力接口、`*Util` 工具入口或所属域服务；调用方不直接读写 NeoForge 附件。
- 事件订阅继续遵循 `event-registration.md`，每个总线、发行侧和事件类型保留唯一入口。
- 将注册、事件入口、运行状态机、渲染表现和网络载荷分开检查，避免通过移动包名掩盖职责耦合。
- 对本批次触及的类补充简洁职责注释，避免一次性为全部历史类添加无意义注释。

### 阶段三：包结构和命名（实体、技能与指挥家首批完成）

- 先迁移无状态工具、数据模型和公开契约，再迁移实体实现、技能适配和客户端类。
- `entity.entity` 的合并目标、`event` 与 `events` 的事件模型归属，以及 `entity_skill` 是否更名，必须以 IDEA 引用结果和当前依赖关系为依据分批执行。
- 每批迁移使用 IDEA 的移动/重命名重构，保持包声明、导入、Mixin 配置和资源引用一致。
- 工具类使用 `*Util`；能力接口、数据附件、技能定义和注册对象保留各自语义命名。

## 完成后的维护约束

- 实体按作用归入 `world.entity` 的对应类别，禁止恢复 `entity.entity`；AI、状态、属性与技能归属见批准清单。
- `event` 只放事件类型和事件数据，`events` 只放自动订阅与有序分发；业务处理仍归属功能域。
- 共用技能归 `world.entity.skill`，具体技能归对应实体作用域，注册归 `registry.entity.skill`；注册 ID、资源路径和能力入口不得因整理分裂。
- 工具全部归根 `util` 及其作用子包，使用 `*Util` 命名，不在其他功能域恢复平行 util 包。
- 不因单纯格式化任务批量移动类；包整理按用户审批的具体批次执行，新增或修改类按上述边界归档，避免覆盖并行修改。
