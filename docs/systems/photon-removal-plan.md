## 2. 当前核对结果与证据边界

- 当前分支为 `dev`，本轮开始时 321 个变更条目，209 个暂存、223 个未暂存、5 个未跟踪，0 冲突。这些计数重叠，不是待删除文件数。
- 五个 Photon 源码入口的初筛共 352 项：346 个 `.java` 与 6 个 `.java~`。其中同时有保留、移除和混合文件，不能整目录删除；备份样式文件不顺带清理。
- `PhotonEffectEditor` 自身是原生 FXEditor 的独立入口/窗口身份，属于保留对象。
- `PhotonEditorTools.bindRuntime` 的 IDEA 调用层级确认会调用 `PhotonAnimationTab.install`
  ；该文件同时引用模型/动画、性能面板、通用曲线、剪贴板、快捷键等。
- `LcPhotonEditorCommand.register` 当前源码会先注册 `LcPhotonProfileCommand`
  ，再注册编辑器入口。该方法调用层级查询超时，未计为完整调用层级核对；上述关系来自实际方法体。
- `LcPhotonMcpCommands` 的 15 个现有 MCP 操作最终进入 `PhotonEffectAutomation`；后者直接引用模型工程、模型资产、模型动画片段和命名动画工具。
- `ClientRuntimeEvents` 同时包含待拆的特效准备/播放/缓冲/模型缓存、保留的性能调试，以及实体 LOD、普通实体动画和其他客户端功能。
- 跨目录引用还涉及 `LcClientAnimations`、`PhotonAnimationTarget`、GeckoLib 适配、`TranslationKeys`、指挥家性能探针及
  Minecraft/GL/KilaGraph Mixin。
- 本轮是依赖初筛，未宣称已完成所有类型、反射注册、序列化入口和第三方调用的删除闭包检查。

后续实施前应为每个文件登记“完整移除 / 完整保留 / 局部拆分 / 待确认”，包含引用方、注册项、资源类型、备份及实际检查。以下按模块给出可供确认的方案。

### 4.4 调试

按保留项保护：

- Minecraft MCP 模块、连接、通用日志/状态/资源检查及编辑器调试。
- 性能命令、采集/导出/面板框架与其对原生运行/GUI 的有效统计。
- 指挥家输入/网络/业务性能探针；它们是调试观察点，不因位于业务文件而连同业务删除。
- `GameRendererMixin` 等只做采样的部分、CPU/GPU 时间查询及对象归属的通用基础；不得与改变管线/绘制行为的实现混为一类。

QueenBeamPerformanceTrial、QueenBeamAllocationCapture、PhotonParticleRuntimeTrial、模型/动画/遮挡回归，以及编辑器测试菜单依赖待删除核心。处理方式列为确认项；不预先默认删除性能工具或所有试验类，也不为保留一个夹具而保留整套运行核心。

## 6. 资源保护与暂时不可用的能力

用户此前明确要求兼容当前文件，该要求继续作为后续重写验收条件。**移除旧实现本身不等于已经完成文件兼容。**
核心移除期间，依赖自定义模型、轨道、控制器和发射器的工程可能暂时不能完整预览或编辑。

实施前必须落实：

1. 新的删除前源码/暂存备份；对不在 Git 快照中的开发资源、未保存工程和包内依赖另行保护，保存清单与哈希。
2. 在原生反序列化之前识别不支持的自定义类型。不能加载后才发现原生读取器已经跳过对象/子轨道。
3. 资源原件保持不变；受影响工程的加载/写入保护、只读提示或明确拒绝加载方式由用户确认。
4. 原生资源扫描、包管理、MCP、保存/另存/导出都不能静默跳过自定义内容后再覆盖原件。
5. 不用假注册、空对象或空轨道把工程伪装为完整可用；不自动转换格式、改名或降级保存。
6. 后续新实现按资源 ID、UUID、参数/轨道/材质/依赖与模型资产往返结果验收，不能以本次资产“未删除”代替可用性。

保留路径扩展和资源浏览不代表允许对缺少核心的工程无保护保存；此为执行前必须解决的依赖边界。
