# Photon 模型特效

## 独立回归测试入口

2026-10-10 起，独立模型、网格和拓扑回归位于 `src/test/java/org/unitego/lobecorp/client/photon/model/validation`，分别为 `PhotonModelRegressionTest`、`PhotonModelMeshRegressionTest`、`PhotonModelTopologyRegressionTest`，共 24 个 JUnit Jupiter 测试方法。原三个 main 入口已移除，通过 IDEA 测试入口或 Gradle `test` 执行，不再随正式模组打包独立算法检查。

`src/main/java` 中的 `PhotonModelRegression.runLoaded()` 只保留 Photon 模组扫描完成后才能执行的大模型 NBT／旧快照兼容检查及其夹具，不纳入普通 JUnit。历史 main 结果仅为历史证据；维护时不能把加载检查直接放进没有 NeoForge 环境的普通测试。实际迁移检查见 [修改记录](changes.md)。

## 运行缓存与采样开销（2026-10-15）

模型 JSON 仍经严格协议和资产校验，`PhotonModelIOUtil` 以完整来源文本为键缓存纯数据副本；读取与写入调用方的资产不会直接成为缓存对象。LRU 同时限制 32 个条目和 4 Mi 字符来源预算，超大单份资产不进入缓存，失败输入不缓存；内容改变自然使用新键。缓存不持有世界、GPU 管线或播放实例，不为兼容添加旧格式分支。

`PhotonModelSamplerUtil.prepare` 创建独占定义副本、校验并预先三角化，运行发射器通过 `sampleForRender(PreparedModel, ...)` 复用拓扑；原可变资产采样入口继续逐次校验，编辑后的定义必须重新准备。同一 JSON 的不可变准备结果可共享，动画姿态仍由实例独立持有。发射器载入、替换或恢复来源时清除准备结果与姿态缓存；无动态部件／骨骼／形状覆盖且几何采样键相同时可复用姿态，世界变换、颜色和透明度仍在绘制时读取。整体透明度为零时先返回，不生成网格；顶点输出复用临时向量，保持逆转置法线和绕序处理。

私有着色器槽缓存材质提交副本，按槽身份、双面、材质文本、纹理、覆盖层及来源混合／深度状态失效；层、顺序、剔除和自定义遮罩控制仍实时复制。原生纹理材质保留实时复制，避免漏掉其可变参数。定义同步和运行状态清理会清除缓存，缓存数量随当前资产槽数量受限。

本轮 IDEA 编译触发结构热替换，既有 `PhotonModelEmitterRuntime` 未执行新增字段初始化器，客户端日志确认 `renderers` 空值导致退出。已将实例缓存改为惰性初始化，静态 JSON 缓存放入独立延迟初始化容器；新加运行字段不得假定既有实例重新执行构造器。客户端随后重新启动并恢复原世界／工程，现场检查相同姿态／材质复用、透明跳过、材质内容／覆盖层／深度／双面变化、控制实时更新和清理失效均符合预期。16 项模型回归通过，覆盖缓存副本隔离、来源变更、准备快照、动态覆盖与循环／钳制透明度；特效侧采样与 GPU 测量边界见 [性能记录](photon-effect-mcp.md#v3-性能优化2026-10-15)。

## 采样池、发射复制与单面剔除（2026-10-15）

运行发射器使用 `sampleForRender`，仅生成其部件或材质分组网格，不输出总网格、拾取顶点表和骨骼显示表；所需的临时姿态计算仍保留，编辑器与 OBJ 导出继续使用完整采样。三角形向量及面角数组在每线程上使用最多两个工作区的有界池，通过 finally 归还；原生 Builder 立即复制输入，所以返回网格不会借用池内数组。没有形状键时直接读取准备快照顶点，无动态覆盖时跳过 ID 列表分配。

同一严格 JSON 的准备拓扑、纹理列表与材质 NBT 归现有 32 条／4 Mi 字符 LRU 共同管理，不另建无限缓存。准备定义没有可变资产出口，编辑读取和材质依赖均返回副本。复制配置遇到完全相同的材质依赖时跳过资产重写；原生资源包改写依赖时必须继续应用，不能用缓存覆盖新路径。失败来源仍允许上一份有效模型参与采样。

无内部几何动画的模型可以跨时间复用姿态，颜色、世界变换和片段透明度仍实时读取；有几何轨道或动态覆盖时继续求值。新增 [PhotonModelCullUtil](../../src/main/java/org/unitego/lobecorp/util/photon/model/PhotonModelCullUtil.java) 只处理普通 TextureMaterial 的有效单面三角形，并计入世界变换的镜像符号。双面、线框、奇异矩阵、自定义材质及可能位移的着色器不进入 CPU 剔除；配对四边面也保留原生判断。

20 项模型回归和 IDEA 编译通过，Data 正常退出。对象池仅限不会逃逸的计算工作区，整套 FXRuntime、仍待引擎移除的粒子和外部播放句柄没有进入池。Spark 的 Windows Java 回退采样不提供 allocation profiler 或 GPU 利用率；实际分配与运行证据见 [本轮修改记录](changes.md#2026-10-15模型采样池绘制精简与发射复制开销)。

## 用法与职责

当前适配 Photon 26.1.2.3／LDLib2 26.1.2.42。模型及材质预览使用新版几何／属性分离网格；底部传输栏直接沿用新增原生组件，步进和跳末尾保留模型片段的小数 tick，原生播放快捷键路由到模型时间轴。发布内容、适配边界和实际检查见[依赖升级](photon-dependency-upgrade.md)。

Photon 的“文件 → 新建 → 模型特效项目”打开独立工程标签；“加载项目”识别 `.mfxproj`、`.mfx` 与 `.obj`。两种编辑器均安装相同文件类型，跨类型打开由所属窗口载入对应编辑器。模型、UV 和动画在同一工程内编辑，标签采用“[模型特效项目] - 模型名称”。未保存工程提供“保存”和“另存为”；保存进入原生另存对话框，创建 `.mfxproj`。打开 OBJ 或 `.mfx` 创建未保存的模型特效工程，采用源文件名，保存不覆盖来源。已保存工程支持原生覆盖保存、另存、关闭确认与最近项目；标题路径和同名区分沿用共享设置。本轮按用户选择不注册旧模型工程／定义后缀或迁移入口。

新建工程默认提供居中的 1×1×1 白模，参考长度／宽度均为 1；8 个共享几何顶点和 6 个基础面属于可编辑网格。新建基本体每个部件使用独立的单个白色纹理槽，所有面共享该槽；多纹理通过显式面分配实现，已有草方块工程不自动迁移。UV 面四角对应贴图四角；画布提供纹理选择器，只显示当前部件使用该纹理的面，模型层级单击只选择部件并刷新检视，双击才切到 UV；场景拾取部件或面保留原有切换及跟随选面纹理的行为。

默认布局为左侧“模型层级／UV／模型资源”，右侧原生“检视面板／历史”，中央提供常规场景与动画场景标签，共用原生 `SceneView`，底部保留原资源目录与模型时间轴。层级复用 TreeList 展示真实部件父子关系；选择部件后在检视面板编辑属性，UV 和动画操作使用各自面板。视图菜单可重新打开已关闭面板；面板标签支持原生拖动停靠、最大化和浮动，场景视图保持在主窗口。窗口尺寸、布局保存、设置与文档入口复用原生编辑器能力。旧布局缺少 `editor.scene` 视图槽时仅在本次加载跳过恢复，随后还原恢复布局的偏好；正常自定义布局继续恢复，不统一重置用户布局。

默认 Ctrl+S 保存模型项目及所属浮动面板的工程；撤销／重做、几何选择与复制删除、框选和取消均使用原生 Keymap 绑定及模型作用域，文本框保留自己的文本撤销。底部资源目录复用原生材质／网格／着色器图／Photon 函数图库，左侧模型资源管理当前资产的材质槽、参数快照与贴图引用；文本粘贴、资源剪贴板、重命名、通知与悬浮样式开关沿用 Photon 共享设置。

需要播放模型时，在 Photon 对象层级新建“模型特效”（类型标识 `lobecorp_model_emitter`），或通过原生 FX 资源入口加载 `.mfx` 定义。原检视器的“编辑模型”打开独立模型特效工程，保留来源特效项目。发射器播放一个模型实例，尺寸、动画时钟和动态属性由各实例独立持有；原 Photon 粒子发射器及 OBJ／glTF 加载路径保持原行为。

- 模型工作区提供基本体、顶点／边／面选择、选择变换、部件／面复制、删除与简单逐面挤出；部件管理轴心、父级、默认变换和局部伸长。
- UV 按面角保存，保留同一几何顶点的 UV 接缝；提供纹理背景、角点／面选择、拖动、数值变换和三轴平面投影。
- 动画工作区提供部件与骨骼 TRS 关键帧、形状键权重和播放预览；时间单位为游戏 tick，允许部分刻。骨骼绑定姿态与动画临时姿态分别编辑，记录关键帧后将临时姿态写入所选片段。模型时间轴直接编辑部件、骨骼、形状权重与整体透明度关键帧；模型动画保持独立的版本 1 数据，不写入特效项目的轨道协议。
- 独立工程复用 LDLib2 的 `IProject`、`ProjectType` 和受限的 `FXEditor` 外壳，支持原生保存／另存为、未保存修改确认和撤销／重做历史。工程持有资产编辑副本；从发射器打开时另复制预览发射器，编辑与播放只更新副本。“应用到发射器”才替换原特效定义并进入其历史，保存模型工程与应用分别处理。应用同时要求来源标签／工程未变，且来源运行时按 UUID 登记的对象仍是同一发射器实例；嵌套对象按运行时登记检查，删除发射器、删除其父节点或替换为同 UUID 的其他实例均不能绕过门禁。来源失效后，独立工程仍可继续编辑、保存和导出。

模型项目保存默认 Photon `RendererSetting`，特效实例可显式覆盖。资产的 `materials` 映射按面上的 `material` 标签提供纹理、`NONE/GRASS` 色调、覆盖层标记及可选 `materialData` 原生材质 NBT 快照；新建白模使用一个纹理槽。预览和运行时按部件／材质分组，复制当前生效的混合／深度管线，再应用槽的纹理或原生材质实例与部件双面设置，不修改共享材质或发射器配置。基础面先提交，覆盖层后提交且不写深度；锁定 Photon 的深度比较为 `LESS_THAN_OR_EQUAL`。UV 画布仅读取实际 `TextureMaterial` 的纹理，着色器槽不伪造 UV 背景。未定义槽的面、没有材质槽的资产及普通 OBJ 沿用当前生效的渲染设置，未知 `usemtl` 标签不会自动创建材质或读取 MTL。

模型资源树列出当前模型的全部材质槽、原生预览缩略与面引用数，未使用槽保留并标记，不列出整个共享资源库。选择槽后在原检视面板编辑；支持新建纹理槽、着色器图材质、自定义着色器材质、从库选入或替换材质、替换 PNG、色调／覆盖层、分配选中面、重命名并同步面引用，以及删除未使用槽。着色器槽直接复用原生 `buildConfigurator` 的实时预览、资源选择与参数控件。全部模型修改经 `session.change` 进入统一撤销／重做与保存；原生参数变更期间保留当前控件，避免每次输入重建检视器。仍被面引用的槽拒绝删除，重命名不得占用其他槽或捕获原有未解析的 OBJ 材质标签。

PNG 通过原生 `ResourceFileImport.resolveOrImport` 解析或导入共享资源包，模型保存稳定的纹理资源标识。从库选入 `UIResourceMaterial` 时先解析原始材质，再通过原生 `IMaterial.CODEC` 保存独立参数快照；普通纹理槽仍只复制纹理标识。着色器图及自定义着色器源文件继续使用共享资源引用。`.mfxproj` 与 `.mfx` 保存参数和引用，复制文件时需提供对应资源包。`.mfxpack` 沿用原生资源收集与打包：派生 `assetDependencies` 提供 PNG 引用，结构化 `assetMaterialDependencies` 提供完整材质 wrapper，载入时将原生打包器改写的资源路径回填 `materialData`。撤销、删除槽或关闭工程不删除共享资源。原生导入器保留源扩展名，外部大写 `.PNG` 目标需改成小写 `.png`，否则资源路径校验拒绝。

## 常规场景与动画场景（2026-10-14）

按用户确认，模型工程沿用特效项目的常规场景／动画场景分工。模型和 UV 工作区属于常规场景；进入中央动画标签或选择动画片段进入动画场景。记住的 `session.selectedClip` 只表示编辑选择，是否应用片段长度、循环和采样由当前场景决定，不能仅凭选择非空推断动画模式。

- 常规场景使用基础模型，默认没有预设结束时间；内容终点为 0，仍可播放、暂停、停止、步进和定位。曾经选过动画不会让常规时钟在该片段末尾暂停；没有活动片段时“跳到末尾”不操作。
- 动画场景编辑及采样当前片段，非循环播放到 duration 暂停，循环播放和暂停保留片段相位；没有片段时仍可定位和运行不限时钟。播放、停止、步进、时间输入和标尺拖动按当前场景处理，不再自行激活动画场景；添加／选择轨道及记录关键帧等动画编辑入口仍进入动画场景。
- 两种场景以及各动画片段分别记住小数 tick 时间、时间轴缩放、水平／垂直滚动和轨道／关键帧选择。切换前结束当前关键帧拖动并保存状态；进入或切换动画恢复该片段位置并暂停，返回常规场景恢复进入前的时间和播放／暂停状态。模型几何与部件选区仍属于同一会话，不因场景切换清空。

`PhotonModelAnimationSceneView` 作为原生停靠标签借用同一个 `SceneView`；世界、相机、`FXRuntime` 和粒子管理器共享，不创建第二套视口、运行实例或 UI 时钟。借用期间暂时关闭场景控件自动释放，退出动画、移除动画标签或关闭工程时先归还原父节点，再恢复原释放策略。标签切换回调与 `PhotonModelEditor.showWorkspace` 共同进入同一模式切换入口，并防止相互回调重入。

`PhotonModelAnimationWorkspace` 管理常规状态与按片段 ID 保存的内存状态；`PhotonModelSceneController.activeClip()` 只在动画场景返回活动片段，时间限制和循环相位统一读取该入口。`PhotonModelTimelineView` 复用 `PhotonTimelineEditAccess` 的原生视图快照，原生恢复会重建轨道，因此模型自有轨道／关键帧选择最后恢复并按当前片段重新校验；重命名迁移对应状态，删除清理失效状态。以上是当前工程会话中的编辑状态，不新增磁盘字段或迁移分支，模型资产版本 1、`.mfxproj`／`.mfx`／`.mfxpack` 协议保持不变。

已确认的原问题是工作区只切换预览采样布尔值，传输控件又无条件调用动画激活回调，而时钟始终读取 `session.clip()`；因此常规播放会切到动画，或被先前选中的片段限时。2026-10-13 放开空片段播放只解决了入口提前返回，未建立两种场景上下文。本次修复以模式、活动片段和保存／恢复生命周期共同隔离；维护时须同时核对采样、时钟和所有传输入口，不能只改面板显示或空轴时长。实际编译、Data 与诊断结果见 [修改记录](changes.md)；场景标签切换、状态恢复及真实输入尚未游戏内验收。

## 模型默认渲染与实例覆盖（2026-10-14）

模型项目的模型检视增加“默认渲染与材质”，复用原生材质列表、混合因子、深度测试／写入、渲染层、层内顺序、顶点排序、合成方式、遮罩和现有遮挡／视深排序扩展。模型项目保存独立 `renderer` 原生 NBT 快照；预览、应用到来源发射器、`.mfx` 定义及 `.mfxpack` 导出均传递同一默认设置。快照通过 `PhotonModelRendererUtil` 的原生持久化深复制，不在模型资产 JSON 内保存不可遍历的渲染字符串；原生打包器可递归收集结构化材质依赖。

发射器 `config.modelRenderer` 保存模型默认值，`overrideRenderer` 默认关闭。特效项目开启“覆盖模型渲染设置”后才显示并使用 `config.renderer` 的实例覆盖；关闭后恢复模型默认。应用模型只更新默认值，保留来源实例已明确选择的覆盖开关和值。原生运行态、视锥剔除和逐部件绘制读取同一生效侧；顺序动画仍使用 `renderer.orderInLayer` 路径并绑定当前生效槽，切换时清理非活动侧的临时覆盖。

部件 `doubleSided` 与 `shading` 属于实际效果属性，始终参与预览和真实特效绘制：双面决定材质副本的背面剔除，阴影按变形后法线调整顶点 RGB，不产生投影阴影；自定义着色器需消费顶点 RGB 才能显示该明暗。私有材质槽仍覆盖各自的纹理或着色器；透明覆盖面继续不写深度。编辑器不再强制打开基础面深度写入，用户设置与真实效果保持同源。

渲染设置编辑使用完整工程历史，初次提交保留当前检视控件，撤销／重做再刷新；关闭或切换检视后的过期控件不能继续提交。按用户确认不兼容旧数据：缺少 `renderer` 节点的模型工程，以及缺少 `modelRenderer` 的模型发射器定义或特效工程对象拒绝读取，不从旧实例配置迁移默认值。资产 JSON 的版本 1 几何／动画协议未改变。

### 部件旋转、缩放与轴心（2026-10-10）

资产包含参考长度／宽度、前向轴、顶点、面角 UV、部件层级、骨骼绑定、顶点权重、形状键及片段关键帧，可选 `materials` 映射及部件 `shading/doubleSided/insideOut` 保持版本 1。旧文件缺省材质为空，部件阴影关、双面开、表面朝向未翻转；JSON 保存、历史和深复制保留材质槽、部件渲染设置和表面朝向，验证纹理资源标识、非空色调和槽数据。未知版本、重复 JSON 字段、非法引用、循环层级、非有限数值和无效简单多边形拒绝导入；骨骼绑定缩放不可为零，动画缩放允许零。

独立 OBJ 导入支持正／负索引、`o/g` 分组、面角 UV 和材质标签。参考长度取前向轴完整跨度，参考宽度取两个横轴中的最大完整跨度，退化维度回退到默认尺寸。OBJ 导出烘焙默认部件变换与默认形状键权重，不采样动画；跨部件共享顶点按部件分开，UV 接缝保留，法线重新计算，面输出为三角形，并烘焙部件负尺寸的绕序。普通 OBJ 不携带扩展材质映射、草色色调、覆盖层或动画属性；OBJ 不保存部件阴影／双面选项；完整编辑数据保存为 `.mfxproj`，模型特效导出 `.mfx` 定义或 `.mfxpack`；文件菜单不再提供裸资产 JSON 导出。

发射器支持内嵌、资源引用和本地文件来源。外部文件导入后保存完整资产 JSON 快照到原 Photon definition，因此 `.mfx`／`.mfxpack` 可携带已经导入的模型数据；普通特效中的模型对象仍随普通特效一起保存；改变来源引用或“重新加载”才更新快照。修改外部文件不会逐帧触发磁盘读取。加载失败保留最后有效数据并显示错误状态。内部资产快照保持 JSON，definition 的 `assetJson` 键使用 UTF-8 NBT 字节数组保存，避免 NBT 字符串的长度上限，并兼容读取旧字符串快照。 `assetDependencies` 从有效快照内的材质贴图派生，供原生 FXPack／资源扫描器遍历；它不是另一份模型来源，反序列化不依赖该派生列表。字节数组内的 JSON 不能直接被原生 NBT 资源遍历器发现，因此维护导出时必须保留此列表。

## 尺寸、锚点与局部变形

### 面角法线采样（2026-10-14）

已确认资产的 `Face.normals` 被保存、复制和交换，但 `PhotonModelSamplerUtil.appendTriangle` 原先总是用三角形面法线输出三个顶点，导致作者指定的平滑法线及硬边未进入渲染。采样现按面角读取法线，并使用尺寸拉伸、归一化权重混合蒙皮和部件层级的组合线性变换的逆转置矩阵；镜像部件按实际绕序修正符号，`insideOut` 继续同时翻转绕序与法线。逐顶点矩阵在同次采样内复用，资产、公开采样结果和文件格式不变。

没有法线、零法线、不可逆尺寸／姿态或非有限结果时回退到采样后的三角形面法线。启用局部伸长、没有部件锚点覆盖且实际长度差非零时，区间起止边界角也回退到最终采样面法线，避免错误复用固定侧或伸长侧的单一缩放导数；该回退不保留作者指定的平滑方向，退化／非有限叉积使用 FALLBACK_NORMAL，insideOut 仍统一反向。形状键目前仅提供位置 delta，没有法线增量，实际顶点变化时继续采用变形后的面法线，不声称支持形状键平滑法线插值。后续维护不能直接用位置矩阵乘法线，尤其要保留非均匀缩放、镜像和退化变换处理。本轮实际检查见 [修改记录](changes.md)。

默认使用模型参考尺寸，导入不归一化几何。取消“使用模型参考尺寸”后，长度／宽度按模型坐标单位解释；原对象的世界变换继续由 Photon 管理。

- 没有局部规则时，整体长度围绕模型原点、起点或终点缩放。
- 启用局部伸长后，指定区间的起端保持，区间内轴向缩放，区间后坐标平移；START 部件固定，END 部件随长度差平移。
- 启用的部件伸长轴必须等于资产前向轴，编辑器改轴时同步全部已启用区间。
- 全局 END 将长度差的位移反向补偿到整个绑定坐标，保持末端位置。锚点约束长度改变，后续部件和骨骼动画仍可移动它。
- 中段缩短最多折叠为零，不翻转；端帽长度形成实际最小总长度。宽度可为零，并同比缩放全部部件的横轴坐标。
- 多个区间分别使用同一长度差，第一版不自动分配串联区间总增量，不提供骨链 IK 或世界空间锁点。

采样顺序为形状键 → 局部长度与宽度 → 骨骼蒙皮 → 部件层级。骨骼蒙皮矩阵使用采样世界变换乘绑定世界变换的逆矩阵；未绑定顶点不变，已绑定权重归一化。部件
TRS 使用轴心，旋转插值采用四元数最短弧。

`SampledModel.boneWorldMatrices`
保存模型空间中的骨骼层级姿态，供视窗直接复用同次采样；计算蒙皮矩阵时复制后乘逆绑定，不修改该姿态映射。原五参、六参构造入口保留，缺省骨骼映射为空。该结果仅在内存中使用，不改变模型
JSON 或工程版本。

## 运行、时间轴与边界

模型工程在原生 `SceneView` 中以真实 `FXRuntime` 播放复制的模型发射器，表面使用 `PhotonModelEmitterRuntime` 与原 Photon
渲染管线。`PhotonModelSceneController` 将会话采样接入预览实例；`PhotonModelPreview` 承担几何选择、选中标记、骨骼辅助显示与原生
TransformGizmo，不另建模型表面渲染器或预览世界。选择覆盖对象直接属于 `SceneEditor`，选择手柄以该 Preview 为父，独立于
`FXRuntime`；Preview 跟随发射器的世界变换，Gizmo
使用手柄的本地位置／旋转／缩放编辑模型坐标。拖动经会话的连续编辑入口，在释放时合并为一条历史记录；几何模式使用基础几何，动画模式采样所选片段与临时姿态。

骨骼以关节点和父子连线显示，未选为半透明青色，选中关节及其父级连线为橙色；使用原生辅助管线并关闭深度测试与写入，内部骨骼仍可见。几何模式显示绑定层级，动画模式与模型共用片段、时间、循环与临时骨骼姿态；预览直接复用已有采样缓存。当前骨骼数据只有绑定
TRS 和父级，没有独立头尾或长度，根骨骼显示为点；重合父子保留关节点并跳过退化连线，选中关节点单独最后提交。此项不增加视窗骨骼拾取或拖动能力。

播放、暂停、重启与定位统一使用原生 `sceneView.particleManager` 时钟。模型小数 tick 定位先交给 `simulateTo` 处理整数部分，再保存小数残量；读取时间时在原生时间上加该残量，不另起 UI 时钟。`ModelSceneViewMixin` 在原生整数定位和 reset 时清零残量，使 S 面板定位与重启不继承旧小数；模型小数定位在原生定位后恢复本次目标的小数部分。仅动画场景的活动非循环片段结束时停在片段末尾，常规场景不读取编辑器记住的片段限制，时间与播放状态回写会话。时间框每 tick 同步 `session.time`，但获得焦点或正在拖动该数字字段时暂停覆盖，避免播放刷新打断输入或数值拖动。

单模型继承 Photon 的延迟、持续、循环、暂停与重启生命周期，接入原 `PhotonEmissionControlAccess` 停止协议。循环软停止在当前周期结束时排空，恢复未移除实例时可取消截止，不创建额外粒子或 Minecraft 实体。

沿用原 Timeline 属性与 [命名动画](photon-named-animations.md) Mixer，动态路径包括：

- `config.parts.<id>.position/rotation/scale`
- `config.bones.<id>.position/rotation/scale`
- `config.morphs.<id>.weight`
- 长度、宽度、颜色、透明度与动画时间等已暴露配置属性。

## 由粒子特效触发模型动画（2026-10-13）

特效项目的普通时间轴及命名动画共用“模型动画”轨道。添加轨道后绑定模型发射器，在片段中选择模型资产内的动画；原生片段的起点、长度和倍率与新增的动画时间偏移共同决定采样时间，单位均为 tick。片段默认不循环，开启后仍遵守模型动画自身的循环标志。时间轴暂停、定位与重新播放沿用原播放器时钟，不额外累计一份动画时间。

片段结束后可选择“恢复默认动画”或“保持末帧”。恢复时撤销当前轨道对模型片段的覆盖，模型默认时钟在受控期间继续推进；保持时固定在片段末尾的采样时间；循环动画恰好结束完整周期时保留该周期末帧，避免取模回到第一帧。单轨道按已开始片段中起点最晚的一项选择，并列时以后列表项为准；它结束并恢复默认后，不重新激活此前的保持片段。同一播放器内后面的轨道覆盖前面的轨道。多个命名播放同时控制同一模型时，优先级较高者生效，同优先级以后启动者生效，命名动画优先于主时间轴。此处选择完整模型片段，不做片段间骨骼混合；已有部件／骨骼／形状键数值属性仍由原 Mixer 合成。
