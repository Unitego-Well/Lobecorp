# 群体事件与深夜清扫

## 2026-11-08 模板触发、开闭幕与尾部生成（当前）

管理员命令新增中文模板入口，原有horde start/stop/clear保留：

```text
/lobecorp 事件 模板触发 深夜清扫
/lobecorp 事件 模板触发 深夜清扫 <位置x y z> <方向yaw>
```

省略参数使用执行位置及朝向；位置为入场线中心，方向为浪潮行进方向，0向南、90向西、180向北、-90向东，支持相对~角度。模板宽500、路线长1000、总计3600逻辑刻（3分钟，包含最后一段浪潮通过）；按现有清道夫速度扣除ceil(1000/speed)收尾刻数后设置生成时长，不改变移动速度。无法在三分钟内通过时拒绝启动。既有通用start的ticks仍表示生成阶段刻数。

午夜触发使用两条命令，不新增自动定时规则：

```text
/time set midnight
/lobecorp 事件 模板触发 深夜清扫
```

也可明确位置/方向，例如：

```text
/lobecorp 事件 模板触发 深夜清扫 ~ ~ ~ 0
```

00:00对应原版midnight（18000日内刻），不把倒计时设为零。

开幕对触发时位于整条计划线路范围内的同维度非旁观玩家播放200刻（10秒），不会对之后进入范围的玩家补播。服务端添加namespaced移动速度临时修饰符，ADD_MULTIPLIED_TOTAL=-1，实际倍率0；开始时朝入场来向转向一次，不持续锁视角。到期、死亡、旁观、断开、更换玩家实例、跨维度、事件清除及服务端清理时移除本功能修饰符，不改基础属性或其他效果。只限制该移动速度属性，不承诺阻止外力、飞行或传送。

客户端复用HordeStatePayload的独立presentation语义分支，不占事件快照序号、不等待路线分页；协议24→25以拒绝不识别新语义的旧端。没有新增网络包或全局输入系统。开幕普通HUD通过NeoForge RenderGuiLayerEvent.Pre临时取消，并跳过本项目Post普通叠加；不写hideGui用户设置。独立Post表现始终最后绘制，换世界/断开清理。

黑幕在屏幕上下沿竖直进入/退出，各占高度12%。上下警告条分别从左/右水平到位，再让中央黑底横幅与三行靛蓝文字淡入；退出先淡出中央内容，再撤走条与黑幕。开幕警告条入场1秒，中央0.5秒淡入、末尾淡出，最后0.5秒撤离，总10秒。结束横幅50刻（2.5秒），不锁速/转向/隐藏普通HUD，不叠加开幕黑幕。结束在整条浪潮通过时通知当前范围内玩家；clear也触发收尾表现。警告斜纹与边框由既有GUI矩形提取绘制，不生成新贴图。

文案三行：标题“靛蓝色的正午”、主名“清道夫”；开始“夜幕降临之际，他们“悄悄地”来到后巷……”；结束“旭日东升之时，半点痕迹都不会剩下……”。通过HordeLang生成中英文，保留用户指定的“正午”。

尾部阶段仍允许真实参战生成。HordeEvent.canSpawnAt以当前位置对应的路线station计算：stopAt+station/speed-tick必须至少100刻，且当前位置必须处于活动波带。目标发现、预约提供者和实际生成都使用此条件；少于5秒则取消新增预约，已存在者沿既有出界/退场规则处理，完全结束再统一退场。stop只提前停止虚拟浪潮生成并进入收尾；clear立即结束。不改变战斗配额、伤害与正常生物清理边界。

## 架构与入口

通用入口为 `HordeEvents.start/stop/snapshot`，事件定义实现 `IHordeEventProfile`。首个定义为 `lobecorp:midnight_cleanup`（深夜清扫）。服务器持有事件、固定线路和正常参战关系，负责真实生物的生成与参战调度，不参与客户端显示分割；虚拟浪潮由客户端按固定线路和统一时间推算，不创建隐藏 Entity，也不保存逐个虚拟单位。客户端每tick只做Mob与本地玩家区域提交，采用玩家所在区块对齐的模拟距离范围，不按线路节点轮转或按目标距离错峰；不新增目标UUID同步。

事件创建后即推进，默认生成6000逻辑刻、宽128格，纵横间距默认各1.8格。线路按起点、途经点、终点构成开放多段，不自动闭合或添加返程段。线路锚点使用向心 Catmull-Rom 和自适应采样，转角处使用更密的样本。到达终点后离场。奔跑速度取事件定义并持久化，清道夫按既有移动属性、奔跑倍率及原版平地摩擦换算稳定速度；生成时长不再改变奔跑速度。收尾时间为最后一批跑完整条线路所需时间，替代此前与生成阶段等长的预估。真实参战实体按 fadeTicks 淡入淡出，虚拟帧不做逐单位透明渐变。未加载区块不暂停时间也不被强加载，关服期间不推进；已有事件保留线路和规则快照。无法绕行时允许虚拟影像沿粗路线穿行，正常实体出生仍检查安全与粗略可达性。

虚拟分布与正常战斗独立。创建或死亡一个正常清道夫不隐藏、移除或扣除某个虚拟编号。普通清道夫不带事件附件，不受事件规则影响。客户端分割筛选排除带事件来源附件的成员（含退场单位），复用现有同步附件，不把所有普通清道夫排除。基础推进速度不改，GPU只叠加连续的个体随机加减速与最大1.5格左右摆动。

## 战斗调度

各目标新规则初始配额1，首次攻击技能启动或受到分配目标的有效伤害后计时，每100刻增援1，默认最多10。参与者死亡立即提高一级并重置计时，预约创建请求占名额。有效成员加预约的单目标硬上限10，转派也不能超过；旧超额成员加载后按既有淡出流程退出，淡出单位立即停止参战并释放名额。旧快照仍保留自己的初始/增援倍率，但不能突破硬上限。

同维度同阵营同类型事件共享配额，先覆盖首人再分配第二、第三人。正常参与者锁定分配目标，第三方攻击仍正常承伤。战斗区域融合后共享转派范围，拆分保留已有分配。没有区域内可分配目标才淡出移除。

正常实体沿目标后方及虚拟浪潮来向一侧选择出生候选，按 16/12/8/4 格分档回退，并受 spawnDistance 下限及实体宽度约束，不使用某个虚拟影像的位置；例如虚拟潮向左移动时在目标右侧生成。生成时立即朝向目标并绑定分配目标。每维度共享100个正常实体软预算、每刻最多2次成功创建和出生工作预算。无法接敌超时和重试冷却默认各100刻；预算排队会暂停无法接敌计时，实际开始处理后才消耗超时窗口。连续出界40刻解除，追击范围只覆盖当前浪潮路段及余量。

淡入淡出均默认5刻。淡入仅影响表现；淡出立即取消技能、关闭AI、碰撞与承伤、释放名额，结束后移除。事件截止取消排队、禁止新增参战，并让存活参与者退出。事件尸体仍禁止复原。玩家模拟距离内、活动浪潮覆盖且不在战斗保护区域的掉落物按既有规则清理。事件清道夫及其击杀产生的尸体，自尸体创建起保留200tick并保存绝对期限；期间不被沿路清扫抢先删除，到期仍在战斗保护内则继续保留，离开保护后清理。事件结束不取消尸体期限；旧事件标记尸体首次加载补保留期，普通无来源尸体不扩大清除。普通活体生物、宠物和载具不删除。战斗保护采用已有分配目标及参战成员AABB加regionMargin；stop/clear命令本身不扩大世界清理范围。

事件单位不允许指挥家登记、收编或控制；检查覆盖服务端目录、实际控制资格和进入世界路径。区块卸载释放存活单位的名额，不作为死亡增援；正常关服保留有效分配。

## 命令

仅管理员可使用：

```text
/lobecorp horde start lobecorp:midnight_cleanup <起点x y z> <终点x y z>
/lobecorp horde start lobecorp:midnight_cleanup <起点> <终点> <ticks> <width> [x,y,z;x,y,z]
/lobecorp horde list
/lobecorp horde stop <event-uuid>
/lobecorp horde clear <event-uuid>
/lobecorp horde stats
```

`stop`进入收尾，`clear`立即结束；命令不直接清理已有尸体，已设定的事件尸体保留期限仍独立继续。API支持途经点及时长、宽度覆盖，不接受种子；没有自然触发或事件编辑器。

## 配置与同步边界

服务端与客户端现行文件、配置分组及归属以[配置结构](configuration.md)为准，事件启动时固定规则快照。当前深夜清扫环境使用七类聚合音效与独立声音/震动范围，具体频率、并发和生命周期只维护在[清道夫音效契约](sweeper-sounds.md#2026-11-07-接入契约)，不由虚拟单位数或可见批次直接放大。

`maximumVisible` 默认 -1，0 关闭主体显示；`rangeChunks` 默认 -1，跟随有效视野距离，显式范围不超过该距离。区域框通过原版F3+B或清道夫浪潮调试条目显示，复用Gizmo管线，不再单独配置debugRanges；仅是显示辅助，不证明出生请求已建立。旧HUD、视觉质量及浪潮文件只向统一文件缺失分组迁移，先备份且保留旧文件，不覆盖统一文件已有分组。

客户端接收完整线路后显示；正常实体沿用原版追踪和现有附件同步，虚拟事件使用独立状态与快照请求。服务端不发送客户端显示区域，不新增目标 UUID 同步。

具体渲染和资源生命周期见[渲染契约](horde-rendering-implementation.md)；历史数据、备份与适用范围见[基准说明](benchmod.md)，全部未完成问题见[问题汇总](horde-issues.md)。
