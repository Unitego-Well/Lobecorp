## 包职责

| 包 | 责任 | 不应承担 |
| --- | --- | --- |
| `api` | 跨域接口、扩展契约 | 实体运行状态 |
| `world.entity` | 实体、AI、导航、状态、属性；具体技能归对应实体作用域 | 注册入口、客户端表现、网络协议 |
| `world.entity.skill` | 共用技能定义、请求、运行实例、效果和连段机制 | HUD 布局、世界目录 |
| `conductor` | 指挥家目录、控制、移动、队形和远程命令 | 客户端绘制细节 |
| `world.hitbox` | 命中框几何、生命周期和效果应用；geometry 收纳形状与尺寸 | 技能状态机 |
| `world.item` / `world.effect` | 世界内物品与状态效果实现 | 注册入口 |
| `animation` | 动画层、状态和过渡 | AI 决策、伤害逻辑 |
| `registry` | NeoForge 注册对象和注册生命周期 | 运行时业务逻辑 |
| `events` | 唯一事件订阅入口和有序分发 | 持久化状态机 |
| `network` | Payload 定义、编解码和协议分发 | 绕过服务端校验修改实体 |
| `client` | HUD、镜头、输入、会话和缓存 | 服务端权威数据 |
| `mixin` | 原版桥接和最小拦截 | 复制业务状态机 |
| `util` | 无状态可复用的 `*Util` 方法 | 持有实体、世界或渲染对象 |

## 调用方向

业务调用优先经过所属域的公开接口或工具入口：

- 指挥控制通过能力接口和 `ConductorUtil`。
- 指挥附件通过 `ConductorAttachmentUtil`。
- 实体技能通过 `EntitySkillAccess` 能力；技能状态机由 `EntitySkillUtil` 内部推进。
- 技能运行数据不写入世界存档；世界目录只保存世界级摘要和待交付记录。
- Mixin 只调用能力、事件分发或工具入口，不长期缓存能力对象。
- 客户端只消费同步快照，不反向修改服务端附件。

## Conductor 子包

- `conductor/ability`：能力契约、目标预览、能力状态和实体技能适配。
- `conductor/data`：世界目录、单位持久化字段和客户端目录快照。
- `conductor/control`：EntityCapability、单位控制、移动、攻击、声波和清理工作。
- `conductor/world`：区块票据与世界级运行状态；`conductor/lifecycle`：目录和战斗生命周期处理。
- `util/conductor`：附件与能力的 `*Util` 统一入口；`network`：指挥命令与目录快照 Payload。

## 注释规则

- 类注释用一句话说明职责和边界。
- 公共方法注释说明输入、输出和副作用；没有额外约束的方法不写重复实现细节。
- 只解释业务原因、生命周期约束或版本敏感点，不记录开发过程和历史替代方案。
- 业务常量、资源 ID、规则参数放在集中管理的位置；注释说明用途，不重复数值含义。
- 注释和类名保持同步；移动或重命名后同时更新引用和文档。

## 整理流程

1. 先读取项目规范、相关 Skill 和 IDEA 诊断。
2. 以职责为单位整理调用边界；包移动前提交来源、目标、涉及类、理由和引用影响的具体计划，得到用户同意后再执行。
3. 每次移动使用 IDEA 重构，检查 Java 引用、Mixin 配置、资源字符串和客户端/服务端边界。
4. 只修改本批次涉及的代码和注释；完成代码修改后通过 IDEA 格式化修改行或涉及类。只有明确授权的项目整理任务才使用包或项目范围，默认关闭额外导入优化和成员重排。
5. 用 IDEA 检查错误、警告、导入、类型和引用；大型修改按 AGENTS.md 通过 IDEA 完成编译、Data 与生成资源检查，小修改不主动运行验证。
6. 修改前查阅 [系统索引](systems/README.md) 并核对当前源码，完成后同步系统文档与修改记录。文档只是索引和参考，不替代源码判断。

## 代码与格式化规则

- 类按功能域和职责分类，必要时在域内建立子包，不把不同职责堆在单一包，也不为每个类机械新建包。
- 工具统一根 `util`，可按作用分包；在统一职责入口下按“作用 → 类型”细分，具体布局见批准的 [迁移清单](java-package-organization-plan.md)。
- 使用空行区分前置条件检查、正常处理和相邻独立逻辑块；保持 `else`、`catch`、`finally` 的语法关联。
- 优先用前置检查和提前返回减少 `if` 嵌套；循环内可提前 `continue`，保持副作用、执行顺序和资源释放语义。
- 方法、构造函数和复杂 lambda 尽量控制在格式化后 100 行以内，复杂逻辑按职责提取独立方法，不通过压缩代码满足行数。
- 用户提供的 JSON 等资源文件、自动生成输出、第三方文件及二进制资源不纳入自动格式化。资源修改保留原始排版，除非用户明确要求格式化对应文件。
- 并行任务按互不重叠的文件范围分工；包移动及跨包引用更新由同一负责人统筹。
- 本轮代码整理的规则入口为 `AGENTS.md`；包迁移须先审批，计划中的内容不视为已实施。
